# Урок 52. Работа с JSON-файлами

До сих пор при работе с текстовыми файлами мы имели дело только с обычным текстом — строками, которые приходилось самим разбирать на части и самим преобразовывать в нужные типы данных. JSON устроен иначе: это формат, специально созданный для хранения структурированных данных — списков и словарей — с сохранением их типов.

## Зачем нужен JSON

JSON (JavaScript Object Notation) изначально появился в мире JavaScript, но давно стал универсальным форматом обмена данными, используемым практически во всех языках программирования, включая Python. Он повсеместно используется для хранения конфигурации программ, обмена данными между сервером и клиентом при работе с сайтами, и просто как удобный способ сохранить структурированные данные — список пользователей, каталог товаров, настройки приложения — в виде, который легко прочитать и человеку, и другой программе.

## Соответствие между JSON и типами данных Python

Здесь важно провести прямую параллель с тем, что мы уже прекрасно знаем из модуля 4. JSON, по сути, использует ту же самую структуру данных, что и словари со списками в Python, только записанную в виде текста:

| JSON | Python |
|---|---|
| объект `{...}` | словарь `dict` |
| массив `[...]` | список `list` |
| строка `"..."` | строка `str` |
| число | `int` или `float` |
| `true` / `false` | `True` / `False` |
| `null` | `None` |

Стоит отдельно обратить внимание на последние две строки: в JSON логические значения пишутся с маленькой буквы (`true`, `false`), а отсутствие значения называется `null`, а не `None`, — но при чтении в Python эти значения автоматически превратятся в привычные `True`, `False` и `None`.

## Модуль json

Работа с JSON в Python требует подключения модуля `json`:

```python
import json
```

## Запись данных в JSON-файл: json.dump()

`json.dump(данные, файл)` записывает переданный объект Python (обычно словарь или список) в файл в формате JSON. Не забываем про кодировку из урока 51 — `encoding="utf-8"` указываем и здесь:

```python
import json

person = {"name": "Егор", "age": 25, "city": "Москва"}

with open("person.json", "w", encoding="utf-8") as file:
    json.dump(person, file)
```

Обратите внимание: `json.dump()` принимает не путь к файлу, а уже открытый файловый объект — то есть его нужно использовать внутри блока `with`, как показано выше, передав вторым аргументом переменную `file`.

Если открыть получившийся файл, внутри окажется не совсем то, что мы ожидали:

```text
{"name": "Егор", "age": 25, "city": "Москва"}
```

Русские буквы превратились в числовые коды вида `Е`, а всё содержимое записано одной строкой. Причины и решение разберём чуть ниже, в разделе про форматированный вывод.

## Чтение данных из JSON-файла: json.load()

`json.load(файл)` делает обратное — читает содержимое JSON-файла и превращает его обратно в объект Python:

```python
import json

with open("person.json", "r", encoding="utf-8") as file:
    person = json.load(file)

print(person)          # {'name': 'Егор', 'age': 25, 'city': 'Москва'}
print(type(person))    # <class 'dict'>
```

Здесь и заключается главное практическое преимущество JSON перед обычным текстом: `person["age"]` будет настоящим числом `25`, а не строкой `"25"`, которую пришлось бы дополнительно преобразовывать через `int()`, как мы делали при разборе текста в уроке 47. JSON сохраняет исходные типы данных сам, без вашего участия.

## Форматированный вывод: параметры indent и ensure_ascii

По умолчанию `json.dump()` записывает все данные в одну строку. Чтобы получить читаемый, аккуратно отформатированный файл, используется параметр `indent`:

```python
import json

data = {"name": "Егор", "hobbies": ["чтение", "программирование"]}

with open("data.json", "w", encoding="utf-8") as file:
    json.dump(data, file, indent=4, ensure_ascii=False)
```

Содержимое `data.json` после запуска:

```json
{
    "name": "Егор",
    "hobbies": [
        "чтение",
        "программирование"
    ]
}
```

`indent=4` задаёт отступ в 4 пробела для вложенных уровней структуры, делая содержимое файла удобным для чтения человеком.

Параметр `ensure_ascii=False` тоже стоит запомнить. По умолчанию (`ensure_ascii=True`) все не-латинские символы записываются в файл в виде кодов `\uXXXX`, как мы видели выше. С `ensure_ascii=False` они сохраняются как есть — читаемыми буквами.

## JSON и кодировка

У `ensure_ascii` и `encoding` есть связь, о которой важно знать:

* При `ensure_ascii=True` (по умолчанию) файл состоит только из символов ASCII, поэтому он прочитается правильно в любой кодировке. Но человеку такой файл читать неудобно.
* При `ensure_ascii=False` в файле лежат настоящие русские буквы — а значит, кодировка снова становится важной. Если записать такой файл без `encoding="utf-8"`, то на компьютере с кодировкой по умолчанию cp1251 он запишется в cp1251, а на другом компьютере или в другой программе прочитается «кракозябрами» или вызовет `UnicodeDecodeError`. Для символов вне кириллицы (например, эмодзи) запись без явной кодировки вообще упадёт с `UnicodeEncodeError`.

Формат JSON по стандарту предполагает кодировку UTF-8, поэтому **для JSON-файлов правило простое: всегда `encoding="utf-8"` и в `open()` при записи, и в `open()` при чтении**. Комбинация `encoding="utf-8"` + `ensure_ascii=False` даёт читаемый файл, который одинаково работает везде.

## Работа со строкой JSON: dumps() и loads()

Иногда данные в формате JSON нужны не как файл, а как обычная строка в памяти программы — например, если данные пришли не из файла, а откуда-то ещё. Для этого существуют `json.dumps()` и `json.loads()` — те же самые функции по смыслу, но работающие со строкой, а не с файлом (буква `s` в конце названия — от string). Кодировка здесь не нужна: файл не открывается, а строки в Python всегда хранят текст, а не байты:

```python
import json

person = {"name": "Мария", "age": 28}

json_string = json.dumps(person, ensure_ascii=False)
print(json_string)          # {"name": "Мария", "age": 28}
print(type(json_string))    # <class 'str'>

restored = json.loads(json_string)
print(restored)             # {'name': 'Мария', 'age': 28}
print(type(restored))       # <class 'dict'>
```

Короткое правило для запоминания: функции без `s` (`dump`, `load`) работают с файлами, функции с `s` (`dumps`, `loads`) — со строками.

## Разбор задачи: каталог товаров

Разберём практическую задачу: сохранить каталог товаров в JSON-файл, а затем загрузить его обратно и найти товары дешевле определённой суммы.

```python
import json


def save_catalog(filename, catalog):
    with open(filename, "w", encoding="utf-8") as file:
        json.dump(catalog, file, indent=4, ensure_ascii=False)


def load_catalog(filename):
    with open(filename, "r", encoding="utf-8") as file:
        return json.load(file)


def filter_by_price(catalog, max_price):
    return [item for item in catalog if item["price"] < max_price]


def main():
    catalog = [
        {"name": "Наушники", "price": 2500},
        {"name": "Мышь", "price": 800},
        {"name": "Клавиатура", "price": 3200}
    ]

    save_catalog("catalog.json", catalog)

    loaded_catalog = load_catalog("catalog.json")
    cheap_items = filter_by_price(loaded_catalog, 3000)

    print(cheap_items)


main()
```

Результат работы:

```text
[{'name': 'Наушники', 'price': 2500}, {'name': 'Мышь', 'price': 800}]
```

Обратите внимание на `filter_by_price()`: она работает с обычным списком словарей и оператором сравнения `<`, не подозревая о существовании файлов или JSON вообще, — она получает уже готовые данные Python, ровно те же самые типы, с которыми мы работали весь модуль 4. Здесь особенно хорошо видно преимущество JSON: `item["price"]` — это сразу число, готовое к сравнению `< 3000`, без каких-либо дополнительных преобразований типов.

## Итоги урока

JSON — формат для хранения структурированных данных, напрямую соответствующий словарям и спискам Python: объект — словарю, массив — списку, а типы значений (числа, строки, `True`/`False`, `None`) сохраняются автоматически при чтении и записи. `json.dump()`/`json.load()` работают с файлами, `json.dumps()`/`json.loads()` — со строками. Параметр `indent` делает записанный файл читаемым для человека, а `ensure_ascii=False` сохраняет не-латинские символы как есть — в этом случае файлы обязательно открываем с `encoding="utf-8"`, и при записи, и при чтении.
