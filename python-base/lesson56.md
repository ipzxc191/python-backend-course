# Урок 56. Изменяемые и неизменяемые аргументы функций. Вложенные функции и nonlocal

В уроке 42 мы убедились: если внутри функции присвоить параметру новое значение, снаружи ничего не меняется. Пример был на числе. Сегодня разберём, что происходит, если параметром окажется список, — и здесь интуиция, только что закреплённая, рискует сломаться, если не разобраться в механизме до конца.

## Проверяем то же самое поведение на списке

Повторим эксперимент из урока 42, но с параметром-списком:

```python
numbers = [1, 2, 3]

def replace_list(numbers):
    numbers = [99, 100]
    print("Внутри функции:", numbers)

replace_list(numbers)
print("Снаружи функции:", numbers)
```

```
Внутри функции: [99, 100]
Снаружи функции: [1, 2, 3]
```

Пока всё в точности повторяет поведение с числом: присваивание параметру нового значения (`numbers = [99, 100]`) не затронуло внешний список. Это по-прежнему то же самое правило — присваивание внутри функции создаёт новую локальную переменную, никак не связанную с внешней.

## А теперь — изменение списка на месте

Изменим пример: вместо присваивания нового значения будем **изменять** список методом, не пересоздавая его:

```python
numbers = [1, 2, 3]

def add_number(numbers):
    numbers.append(99)
    print("Внутри функции:", numbers)

add_number(numbers)
print("Снаружи функции:", numbers)
```

```
Внутри функции: [1, 2, 3, 99]
Снаружи функции: [1, 2, 3, 99]
```

На этот раз внешний список действительно изменился! На первый взгляд это противоречит всему, что мы только что повторили из урока 42, — но противоречия здесь на самом деле нет.

## Это не два разных правила, а одно и то же правило

Вот ключевая мысль этого раздела, и её стоит понять до конца, а не просто запомнить как исключение. Когда список передаётся в функцию, параметр не получает **копию** списка — он получает ссылку на **тот же самый** объект списка, что и снаружи. Внутри функции переменная `numbers` и внешняя переменная `numbers` — это по-прежнему два независимых имени (как мы и говорили в уроке 42), но оба этих имени в данный момент указывают на один и тот же список в памяти.

- Если внутри функции выполнить **присваивание** (`numbers = [99, 100]`) — локальное имя `numbers` начинает указывать на совершенно новый, другой список, а внешнее имя `numbers` как указывало на старый список, так и продолжает на него указывать. Изменений снаружи нет.
- Если внутри функции выполнить **изменение объекта на месте** (`numbers.append(99)`) — никакого нового объекта не появляется; правится тот же самый список, на который указывают сразу оба имени, внутреннее и внешнее. Изменение видно отовсюду, откуда есть ссылка на этот список, в том числе снаружи функции.

Это ровно тот же принцип, который мы уже увидели в задаче 5 прошлого урока, только теперь — на уровне параметров функции, а не глобальных переменных. С числами, строками и кортежами такого "противоречия" никогда не возникает по одной простой причине: они неизменяемы, и у них попросту нет способа "измениться на месте" — единственное, что с ними вообще можно сделать, это присвоить новое значение, а присваивание, как мы уже знаем, никогда не затрагивает внешнюю переменную. Разница в поведении, которую мы только что наблюдали, — это не два разных правила для разных типов, а одно и то же правило, которое выглядит по-разному в зависимости от того, есть ли у типа данных возможность изменяться на месте вообще.

## Известная ловушка: изменяемое значение по умолчанию

Здесь стоит показать классическую и очень коварную ошибку, прямо связанную с этой темой, — использование изменяемого значения (например, пустого списка) в качестве значения параметра по умолчанию:

```python
def add_item(item, items=[]):
    items.append(item)
    return items

print(add_item("яблоко"))   # ['яблоко']
print(add_item("банан"))    # ['яблоко', 'банан'] — а не ['банан']!
```

Второй вызов выводит не только что добавленный банан, а оба элемента сразу, хотя список `items` при каждом вызове, казалось бы, должен создаваться заново пустым. На деле список по умолчанию (`[]` в объявлении функции) создаётся **один-единственный раз**, в момент объявления функции, а не при каждом её вызове, — и все вызовы, не передающие свой собственный список явно, используют и изменяют один и тот же, общий для всех вызовов список.

Стандартное решение — использовать в качестве значения по умолчанию `None`, а настоящий пустой список создавать уже внутри тела функции:

```python
def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

print(add_item("яблоко"))   # ['яблоко']
print(add_item("банан"))    # ['банан'] — теперь корректно
```

Здесь оператор `is` используется для сравнения с `None` — это общепринятая практика в Python (`is` мы не разбираем подробно в этом курсе, но для сравнения с `None` он используется почти всегда именно в такой форме). Каждый вызов без явного аргумента `items` теперь действительно получает новый пустой список, создаваемый заново внутри функции.

## Вложенные функции

Функцию можно объявить прямо внутри другой функции — такая функция называется вложенной:

```python
def outer_function():
    message = "Привет из внешней функции"

    def inner_function():
        print(message)

    inner_function()

outer_function()
# Привет из внешней функции
```

Здесь `inner_function()` свободно читает переменную `message`, хотя эта переменная объявлена не внутри самой `inner_function()`, а в окружающей её функции `outer_function()`. Это прямое продолжение того же правила, что мы разбирали в прошлом уроке для глобальных переменных: чтение переменной из окружающей области видимости работает без каких-либо специальных объявлений, только теперь «окружающая область» — это не глобальное пространство имён всего файла, а локальное пространство имён внешней функции.

## nonlocal: изменяем переменную окружающей функции

Как и с глобальными переменными, ситуация меняется, как только речь заходит не о чтении, а о присваивании. Если внутри вложенной функции просто присвоить значение переменной с тем же именем, что и у переменной внешней функции, — по уже знакомому нам правилу это создаст новую, отдельную локальную переменную внутри вложенной функции, не затронув переменную снаружи неё.

Чтобы действительно изменить переменную окружающей функции, используется оператор `nonlocal` — прямой аналог `global`, но настроенный на ближайшую окружающую функцию, а не на глобальное пространство имён всего файла:

```python
def process_all():
    total = 0

    def add(value):
        nonlocal total
        total = total + value

    add(5)
    add(10)
    add(3)

    print(total)

process_all()
# 18
```

Без строки `nonlocal total` присваивание `total = total + value` внутри `add()` создало бы отдельную локальную переменную `total`, никак не влияющую на переменную `total` из `process_all()`, — и после трёх вызовов `add()` итоговое значение `total`, выводимое в `process_all()`, так и осталось бы равным `0`. `nonlocal` устраняет эту проблему, явно связывая присваивание внутри `add()` с переменной из окружающей её функции.

## Итоги урока

При передаче в функцию списка (или любого другого изменяемого типа) параметр указывает на тот же самый объект, что и переменная снаружи, — поэтому изменение объекта на месте (например, через `append()`) видно и снаружи функции, тогда как присваивание параметру нового значения, как и раньше, снаружи не отражается. Это не два разных правила, а одно и то же правило про присваивание и изменение на месте, просто по-разному проявляющееся для изменяемых и неизменяемых типов. Изменяемое значение по умолчанию (например, пустой список) в параметре функции создаётся лишь однажды и разделяется между всеми вызовами — во избежание этой ошибки в качестве значения по умолчанию используют `None`, создавая настоящий пустой контейнер уже внутри функции. Функцию можно объявить внутри другой функции; вложенная функция свободно читает переменные окружающей функции, а для их изменения требуется оператор `nonlocal`, работающий по тому же принципу, что и `global`, но применительно к ближайшей окружающей функции, а не ко всему файлу.
