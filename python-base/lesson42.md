# Урок 42. Параметры функции: обособленность функции, параметр ≠ внешняя переменная. Аннотации и docstring

В задаче 5 прошлого урока мы схитрили: функция называлась `get_square`, но число 5, которое она возводила в квадрат, было жёстко зашито внутри неё самой — фактически это было почти обманом, потому что настоящего переиспользования не получилось: вызвать `get_square()` для другого числа было попросту невозможно. Пора это исправить по-настоящему — с помощью параметров.

## Параметры: передаём данные внутрь функции

Параметр — это переменная, которую можно указать в скобках при объявлении функции; она получает значение снаружи, в момент вызова:

```python
def get_square(number):
    return number ** 2

print(get_square(5))    # 25
print(get_square(9))    # 81
print(get_square(12))   # 144
```

Теперь `get_square` — по-настоящему переиспользуемая функция: одна и та же логика применяется к любому числу, переданному при вызове, без единой правки внутри самой функции. Значение, указанное в скобках при вызове (`5`, `9`, `12`), называется **аргументом** — это конкретное значение, которое передаётся в параметр функции на этот раз.

## Ключевая сложность этой темы: функция обособлена

Вот момент, ради которого во многом и написан этот урок, — он часто ломает интуицию новичков сильнее, чем что-либо ещё в теме функций. Функция — это обособленный, изолированный мир: параметр внутри функции — это отдельная переменная, которую функция **создаёт сама для себя** в момент вызова, и она никак не связана с переменной снаружи, даже если у них совпадает имя.

Рассмотрим наглядный пример:

```python
x = 5

def change_x(x):
    x = x + 100
    print("Внутри функции:", x)

change_x(x)
print("Снаружи функции:", x)
```

```
Внутри функции: 105
Снаружи функции: 5
```

Внутри функции `x` действительно стало равно `105` — но это никак не повлияло на внешнюю переменную `x`, которая как была равна `5`, так и осталась. Хотя имя переменной внутри функции и снаружи неё совпадает, это **две совершенно разные переменные**, которые просто случайно называются одинаково. Когда мы вызвали `change_x(x)`, функция получила значение `5` и создала для себя собственную переменную `x`, в которую это значение было положено, — а дальше всё, что происходит с этой внутренней переменной, остаётся полностью внутри функции и никак не выходит наружу.

Это можно сформулировать так: **параметр — это не то же самое, что переменная снаружи, даже с идентичным именем; параметр — это переменная, которую функция заводит для себя сама, а мы лишь кладём в неё какие-то данные при вызове.** Функция работает со своей собственной копией переменной, а не с оригиналом снаружи.

## Затравка на будущее: обычно функция ничего не помнит

Раз уж мы заговорили о том, что происходит внутри функции, стоит упомянуть один факт, к которому мы вернёмся значительно позже, в модуле про декораторы: обычно функция ничего не помнит между вызовами — при каждом новом вызове все её внутренние переменные создаются заново, с нуля, как будто предыдущего вызова никогда и не было. Позже в курсе мы увидим, что это поведение можно изменить — но пока, на этом этапе, вам достаточно знать, что это стандартное, ожидаемое поведение любой обычной функции.

## Аннотации: подсказки о типах, необязательные к исполнению

Внутри скобок при объявлении функции можно, при желании, указать ожидаемый тип параметра, а после скобок — тип возвращаемого значения. Такие подсказки называются **аннотациями**:

```python
def get_square(number: int) -> int:
    return number ** 2
```

Здесь `number: int` подсказывает, что параметр `number` ожидается целым числом, а `-> int` — что функция должна вернуть целое число. Важно понимать: аннотации — это именно подсказки, а не строгая проверка. Python не станет останавливать программу с ошибкой, даже если вы передадите в функцию что-то другое:

```python
def get_square(number: int) -> int:
    return number ** 2

print(get_square(2.5))   # 6.25 — сработает, несмотря на аннотацию int
```

Аннотации нужны в первую очередь для того, чтобы человеку, читающему код (в том числе вам самим спустя время), было проще понять, что функция ожидает на входе и что вернёт на выходе, — а также для того, чтобы редакторы кода могли подсказывать это заранее, ещё до запуска программы. Использовать аннотации не обязательно, но это хорошая, распространённая привычка.

## Docstring: описание функции внутри неё самой

Ещё один способ документировать функцию — строка-описание сразу после `def`, заключённая в тройные кавычки, называемая **docstring**:

```python
def get_square(number):
    """Возвращает квадрат переданного числа."""
    return number ** 2
```

Docstring не влияет на работу функции — это просто текстовое описание того, что функция делает, размещённое прямо внутри неё, в самом естественном для чтения месте. Хорошая привычка — писать короткий docstring для функций, назначение которых не следует сразу и однозначно из одного лишь имени.

## Итоги урока

Параметр — переменная, указанная в скобках при объявлении функции, которая получает значение (аргумент) в момент вызова. Функция обособлена: параметр — это отдельная, собственная переменная функции, никак не связанная с одноимённой переменной снаружи, даже если имена совпадают, — изменения параметра внутри функции не отражаются на внешней переменной. Аннотации (`параметр: тип`, `-> тип`) — необязательные подсказки о типах, не проверяемые Python принудительно, но полезные для читаемости кода. Docstring — строковое описание функции сразу после `def`, документирующее её назначение.

В следующем уроке мы разберём разные способы передачи аргументов функции — позиционные, именованные и со значениями по умолчанию.
