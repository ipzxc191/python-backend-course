# Урок 55. Пространство имён. Глобальная и локальная область видимости

В уроке 42 мы своими глазами видели: переменная-параметр внутри функции не связана с одноимённой переменной снаружи, даже если у них совпадает имя. Тогда мы просто зафиксировали этот факт как правило. Сегодня разберём механизм, который за этим стоит, — пространства имён и области видимости.

## Что такое пространство имён 

**Пространство имён** — это, по сути, словарь, связывающий имена переменных с их значениями, — та же самая идея, что и словарь из модуля 4, только используемая самим Python внутри себя для отслеживания того, какое имя на что сейчас ссылается. У программы не одно общее пространство имён на все случаи жизни, а несколько отдельных, не пересекающихся друг с другом.

**Глобальное пространство имён** — это то, что находится на самом верхнем уровне вашего файла, вне каких-либо функций:

```python
x = 10   # переменная x попадает в глобальное пространство имён

def some_function():
    ...
```

**Локальное пространство имён** создаётся заново при **каждом вызове** функции и существует, только пока функция выполняется, — как только функция завершает работу (возвращает значение или доходит до конца), её локальное пространство имён полностью уничтожается вместе со всеми переменными внутри него. Это прямое объяснение той самой "затравки" из урока 42 — того факта, что функция обычно ничего не помнит между вызовами: ей попросту негде это помнить, её локальное пространство имён не переживает завершение вызова.

## Функция свободно читает глобальные переменные

Здесь стоит сразу разграничить чтение и запись — это разные, несимметричные ситуации. **Прочитать** значение глобальной переменной внутри функции можно без каких-либо специальных действий:

```python
x = 10

def show_x():
    print(x)   # свободно читаем глобальную переменную

show_x()   # 10
```

Функция сначала ищет имя `x` в своём локальном пространстве имён, не находит его там, и тогда Python автоматически поднимается на уровень выше — в глобальное пространство имён — и находит `x` уже там.

## А вот присваивание — совсем другая история

Как только внутри функции появляется **присваивание** имени, ситуация меняется принципиально — именно это мы и наблюдали в уроке 42:

```python
x = 10

def change_x():
    x = 99   # это создаёт НОВУЮ локальную переменную x, а не меняет глобальную
    print("Внутри функции:", x)

change_x()
print("Снаружи функции:", x)
```

```
Внутри функции: 99
Снаружи функции: 10
```

По умолчанию, если внутри функции встречается строка вида `имя = значение`, Python создаёт **новую переменную в локальном пространстве имён** этой функции, никак не трогая одноимённую переменную снаружи, даже если она существует. Функция не "не может дотянуться" до глобальной переменной — дело в том, что присваивание всегда создаёт локальное имя по умолчанию, и оно просто перекрывает (внутри самой функции) видимость глобального имени с тем же названием, а не изменяет его.

## Оператор global: явно указываем, что имя — глобальное

Если действительно нужно изменить именно глобальную переменную изнутри функции, а не создать локальную копию, используется оператор `global`:

```python
counter = 0

def increment():
    global counter
    counter = counter + 1

increment()
increment()
increment()

print(counter)   # 3
```

Строка `global counter` явно сообщает Python: «имя `counter` внутри этой функции относится не к новой локальной переменной, а к той самой глобальной переменной `counter`». После такого объявления присваивание `counter = counter + 1` действительно изменяет глобальную переменную, и это изменение сохраняется после завершения функции — то самое исключение из общего правила «функция ничего не помнит между вызовами», потому что здесь речь идёт не о локальной, а о глобальной переменной.

## Коварная ловушка: UnboundLocalError

Вот особенно неочевидный момент, который стоит разобрать отдельно, потому что он ломает интуицию сильнее прочего. Если внутри функции переменной **присваивается** значение хотя бы один раз — Python считает эту переменную локальной **для всей функции целиком**, даже для строк кода, расположенных выше самого присваивания:

```python
x = 10

def broken_function():
    print(x)     # ожидаем увидеть глобальную x, равную 10
    x = 20       # но раз здесь есть присваивание...
    print(x)

broken_function()
# UnboundLocalError: local variable 'x' referenced before assignment
```

Ошибка возникает уже на первой строке `print(x)`, хотя присваивание находится ниже по коду! Причина в том, что Python заранее, ещё до фактического выполнения функции, просматривает всё её тело и видит, что где-то внутри есть присваивание имени `x` — и раз так, `x` считается локальной переменной на всём протяжении функции, начиная с самой первой строки. К моменту первого `print(x)` эта локальная переменная ещё не успела получить значение (присваивание идёт только следующей строкой), и Python не станет в этой ситуации «на всякий случай» подглядывать в глобальное пространство имён — раз имя уже помечено как локальное, оно остаётся локальным целиком, без исключений.

Если бы в этой функции действительно требовалось сначала прочитать глобальную `x`, а затем создать её изменённую локальную копию под тем же именем, — потребовалось бы либо использовать другое имя для локальной переменной, либо, если целью было именно изменение глобальной переменной, — явно объявить `global x` в начале функции.

## Разумное использование global

Здесь уместна короткая, честная оговорка. Хотя `global` — рабочий и иногда необходимый инструмент, злоупотреблять им не стоит: функции, которые полагаются на изменение глобальных переменных, менее самодостаточны и предсказуемы, чем функции, получающие данные через параметры и отдающие результат через `return`, — тот самый принцип обособленности функции, который мы разбирали в уроке 42. Там, где можно обойтись параметром и возвращаемым значением, это обычно предпочтительнее использования `global`.

## Итоги урока

Пространство имён — это связка имён переменных с их значениями; глобальное пространство имён существует на протяжении всей программы, а локальное создаётся заново при каждом вызове функции и уничтожается по его завершении. Функция может свободно читать глобальные переменные без специальных объявлений, но присваивание внутри функции по умолчанию создаёт новую локальную переменную, даже при совпадении имени с глобальной. Оператор `global` явно указывает, что присваивание должно затронуть именно глобальную переменную. Если переменной присваивается значение хотя бы в одном месте функции, Python считает её локальной для всей функции целиком, что может привести к ошибке `UnboundLocalError` при попытке прочитать её до момента присваивания.

В следующем уроке мы продолжим тему областей видимости — разберём разницу в поведении изменяемых и неизменяемых аргументов функций, а также вложенные функции и оператор `nonlocal`.
