# Урок 43. Позиционные и именованные аргументы. Аргументы по умолчанию

В прошлом уроке мы передавали аргументы функциям, просто перечисляя значения по порядку. Сегодня разберём, что стоит за этим порядком, какую альтернативу ему предлагает Python, и как сделать некоторые аргументы необязательными.

## Позиционные аргументы: порядок имеет значение

То, как мы вызывали функции до сих пор, называется передачей аргументов **по позиции**: первое переданное значение попадает в первый параметр, второе — во второй, и так далее, строго по порядку:

```python
def get_area(length, width):
    return length * width

print(get_area(6, 4))   # 24
```

Здесь важно понимать: `6` становится `length`, а `4` — `width`, потому что они стоят на первой и второй позиции соответственно, а вовсе не потому, что Python как-то догадывается, какое число — длина, а какое — ширина.

Вот в чём коварство позиционных аргументов: если случайно перепутать порядок, Python **не выдаст ошибку**, если оба значения подходят по типу, — он просто молча посчитает не то, что вы имели в виду:

```python
def get_full_name(first_name, last_name):
    return f"{first_name} {last_name}"

print(get_full_name("Олег", "Смирнов"))   # Олег Смирнов — верно
print(get_full_name("Смирнов", "Олег"))   # Смирнов Олег — технически сработало, но перепутано местами
```

Ошибки здесь нет никакой — оба вызова совершенно корректны с точки зрения Python, потому что оба аргумента являются строками, и функция с готовностью подставит их в том порядке, в каком они переданы. Заметить, что аргументы перепутаны местами, можно только по смыслу результата, а не по какому-либо сообщению об ошибке — и это одна из причин, по которой при большом количестве параметров позиционная передача становится рискованной.

## Именованные аргументы: явно указываем, что есть что

Чтобы избежать подобной путаницы, аргумент можно передать **по имени**, явно указав, какому параметру он предназначен:

```python
def get_full_name(first_name, last_name):
    return f"{first_name} {last_name}"

print(get_full_name(first_name="Олег", last_name="Смирнов"))
print(get_full_name(last_name="Смирнов", first_name="Олег"))
```

Оба вызова дадут одинаковый, корректный результат — `Олег Смирнов`, — потому что порядок именованных аргументов не имеет значения: Python сопоставляет их с параметрами не по позиции, а по явно указанному имени. Это особенно полезно для функций с несколькими параметрами, где легко забыть, в каком порядке они были объявлены, — именованные аргументы делают вызов самодокументируемым: сразу видно, что есть что, без необходимости заглядывать в объявление функции.

## Можно смешивать: сначала позиционные, потом именованные

Позиционные и именованные аргументы можно комбинировать в одном вызове, но с одним строгим правилом: все позиционные аргументы должны идти раньше именованных.

```python
def get_area(length, width):
    return length * width

print(get_area(6, width=4))   # 24 — допустимо
print(get_area(length=6, 4))
# SyntaxError: positional argument follows keyword argument
```

Второй вызов недопустим: как только начались именованные аргументы, вернуться обратно к позиционным в этом же вызове уже нельзя.

## Значения по умолчанию: необязательные параметры

Параметру можно задать значение по умолчанию прямо при объявлении функции — тогда при вызове этот аргумент можно вообще не указывать, и будет использовано значение по умолчанию:

```python
def greet(name, greeting="Привет"):
    print(f"{greeting}, {name}!")

greet("Олег")                    # Привет, Олег!
greet("Мария", "Добрый день")     # Добрый день, Мария!
```

Если аргумент для `greeting` не передан, используется значение по умолчанию — `"Привет"`. Если передан — оно замещает значение по умолчанию на этот конкретный вызов.

## Важное правило порядка: обязательные параметры — перед необязательными

При объявлении функции параметры со значением по умолчанию обязательно должны идти **после** параметров без значения по умолчанию — в противном случае Python не поймёт, какое значение к чему относится, и не позволит объявить такую функцию вовсе:

```python
def greet(greeting="Привет", name):
    print(f"{greeting}, {name}!")
# SyntaxError: non-default argument follows default argument
```

Правильный порядок — все обязательные параметры сначала, а параметры со значением по умолчанию — в конце списка параметров, как и было в примере с `greet(name, greeting="Привет")` выше.

## Комбинируем: несколько значений по умолчанию

Значений по умолчанию может быть несколько, и указывать при вызове можно любое их подмножество, обязательно по имени, если пропускаете что-то посередине:

```python
def create_profile(name, age=18, city="Не указан"):
    return f"{name}, {age} лет, город: {city}"

print(create_profile("Олег"))
# Олег, 18 лет, город: Не указан

print(create_profile("Мария", city="Казань"))
# Мария, 18 лет, город: Казань

print(create_profile("Дмитрий", 25, "Москва"))
# Дмитрий, 25 лет, город: Москва
```

Во втором вызове параметр `age` пропущен (используется значение по умолчанию), а `city` указан по имени — иначе Python не понял бы, что второе переданное значение относится именно к `city`, а не к `age`.

## Итоги урока

Позиционные аргументы передаются по порядку и сопоставляются с параметрами по своей позиции — перепутать их местами легко и незаметно, если типы значений совпадают, поскольку ошибки при этом не возникает. Именованные аргументы передаются с явным указанием имени параметра и не зависят от порядка, что делает вызов функции понятнее и надёжнее. Позиционные аргументы в вызове должны предшествовать именованным. Параметр может получить значение по умолчанию, которое используется, если аргумент не передан при вызове; при объявлении функции параметры со значением по умолчанию должны идти после параметров без значения по умолчанию.

В следующем уроке мы разберём, как принимать в функцию заранее неизвестное количество аргументов — с помощью `*args` и `**kwargs`.
