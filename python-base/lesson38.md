# Урок 38. Генераторное выражение: состояние и ленивые вычисления

Все генераторы, с которыми мы работали до сих пор — списка, словаря, множества — ведут себя одинаково в одном важном смысле: они сразу, целиком строят готовый контейнер в памяти. Сегодня мы познакомимся с их близким родственником, который устроен принципиально иначе, — генераторным выражением. Это самый концептуально тяжёлый материал модуля, но именно он лучше всего показывает, что скрывается за уже привычными для вас конструкциями.

## Тот же синтаксис, но с круглыми скобками

Возьмём уже знакомый генератор списка и просто заменим квадратные скобки на круглые:

```python
numbers = [1, 2, 3, 4, 5]

squares_list = [n ** 2 for n in numbers]
squares_genexpr = (n ** 2 for n in numbers)

print(squares_list)      # [1, 4, 9, 16, 25]
print(squares_genexpr)   # <generator object <genexpr> at 0x...>
```

Разница в результате разительная. `squares_list` — это полноценный, готовый список: все пять квадратов уже вычислены и лежат в памяти. А `squares_genexpr` — это вовсе не список и не набор готовых значений, а особый объект, который лишь **умеет** их вычислить, когда его об этом попросят, но пока ничего не вычислил.

## Генераторное выражение — это итератор

Здесь стоит вернуться к уроку 26, где мы разбирали итераторы и `iter()`/`next()`. Генераторное выражение — это готовый итератор: его можно напрямую передать в `next()`, без предварительного вызова `iter()`:

```python
squares_genexpr = (n ** 2 for n in [1, 2, 3])

print(next(squares_genexpr))   # 1
print(next(squares_genexpr))   # 4
print(next(squares_genexpr))   # 9

print(next(squares_genexpr))
# StopIteration
```

Каждый вызов `next()` вычисляет **ровно одно** следующее значение — не все сразу, а именно то, которое запрошено прямо сейчас, — и лишь после этого вычисляется следующее, когда `next()` будет вызван снова. Это и называется **ленивыми вычислениями**: значения появляются по требованию, в час по чайной ложке, а не все скопом заранее.

## Перебор циклом for работает как обычно

Как и с любым другим итератором из урока 26, генераторное выражение прекрасно перебирается через `for` — цикл сам, автоматически, вызывает `next()` на каждом шаге, пока не поймает `StopIteration`:

```python
squares_genexpr = (n ** 2 for n in [1, 2, 3, 4])

for value in squares_genexpr:
    print(value)
```

```
1
4
9
16
```

## Важная особенность: генератор нельзя использовать повторно

Вот ключевое практическое отличие от списка, о котором легко забыть. Список можно перебирать сколько угодно раз — он никуда не девается после первого прохода. Генераторное выражение, напротив, «расходуется» по мере использования:

```python
squares_genexpr = (n ** 2 for n in [1, 2, 3])

first_pass = list(squares_genexpr)
print(first_pass)   # [1, 4, 9]

second_pass = list(squares_genexpr)
print(second_pass)   # [] — пусто!
```

После того как все значения уже были извлечены (в данном случае — превращением в список функцией `list()`), генератор оказывается полностью «пройденным»: внутри него не осталось значений, которые можно было бы отдать снова, и повторный проход просто ничего не находит. Если нужно пройтись по тем же данным ещё раз, генератор придётся создать заново.

## Разница в памяти: что на самом деле хранится

Теперь — то, ради чего этот урок и был задуман. Список хранит все свои элементы одновременно, целиком, а генератор хранит нечто гораздо меньшее — своё **состояние**: на каком шаге он сейчас находится, откуда брать следующее значение и по какой формуле его вычислять. Убедиться в этом можно с помощью функции `getsizeof()` из модуля `sys` — заимствуем её ненадолго, хотя подробно с модулем `sys` познакомимся значительно позже в курсе, — она показывает, сколько байт памяти занимает объект:

```python
import sys

numbers_list = [n for n in range(1000000)]
numbers_genexpr = (n for n in range(1000000))

print(sys.getsizeof(numbers_list))      # около 8 000 000+ байт
print(sys.getsizeof(numbers_genexpr))   # около 200 байт
```

Разница колоссальная, и дело не в том, что генератор «обманывает» и на самом деле не способен дать все эти значения, — он действительно способен отдать все миллион чисел, просто делает это по одному, вычисляя каждое непосредственно в момент запроса, вместо того чтобы держать в памяти сразу весь миллион готовых чисел одновременно.

## Почему иногда выгоднее хранить состояние, а не готовые данные

Возникает вопрос: если генератор способен дать те же самые значения, что и список, зачем вообще нужен список — может, генератор всегда лучше? Не совсем. У списка есть то, чего лишён генератор, — возможность обратиться к любому элементу по индексу в любой момент, перебирать данные многократно, знать длину заранее через `len()`. Генератор — это, по сути, одноразовый, «расходуемый» поток значений, специально предназначенный для одного конкретного прохода.

Генератор особенно выгоден тогда, когда данные нужны ровно один раз, а их потенциальный полный объём либо огромен, либо вообще не важен целиком — важна лишь возможность пройтись по ним один раз, шаг за шагом:

```python
total = sum(n ** 2 for n in range(1000000))
print(total)
```

Здесь `sum()` (с ней подробнее познакомимся в следующем модуле) получает генераторное выражение прямо в качестве аргумента, без отдельных скобок для генератора, — и вычисляет сумму, ни разу не создавая миллион чисел в виде готового, полностью материализованного списка в памяти. Числа появляются по одному, тут же участвуют в сумме и тут же становятся ненужными — программе никогда не приходится держать в памяти больше одного числа одновременно, вместо того чтобы хранить сразу миллион.

## Итоги урока

Генераторное выражение (`(выражение for переменная in последовательность if условие)`) синтаксически похоже на генератор списка, но не строит контейнер сразу, а является готовым итератором, вычисляющим значения по одному, по требованию, — это называется ленивыми вычислениями. Его можно передавать в `next()` напрямую или перебирать циклом `for`, но, в отличие от списка, использовать повторно после полного прохода уже нельзя. Главное практическое отличие от готового контейнера — экономия памяти: генератор хранит не сами данные, а лишь состояние, необходимое для вычисления следующего значения, что особенно выгодно, когда данные нужны только для одного прохода, а их объём может быть очень большим.

Эта идея — что данные не обязаны существовать целиком и сразу, а могут порождаться постепенно, по требованию, — станет только заметнее по мере роста абстракций в курсе. В следующем модуле, при разборе функций, мы снова столкнёмся с похожим принципом: функция тоже не выполняется сама по себе, пока её явно не вызовут, и точно так же скрывает свою внутреннюю работу за простым синтаксисом снаружи.
