# Урок 57. Модули: импорт, разделение программы, константы, __main__. Пакеты и __init__.py

До сих пор вся наша программа умещалась в один файл. По мере роста программы это становится неудобно — код превращается в длинное, трудно обозримое полотно. Сегодня мы разберём, как разделить программу на несколько файлов и подключать код одного файла в другом, а заодно — несколько сопутствующих тем, которые естественно возникают вместе с этим.

## Что такое модуль

**Модуль** — это, по сути, любой файл с расширением `.py`. Имя файла (без расширения) становится именем модуля, под которым его можно подключить в другом файле. Мы уже подключали модули на протяжении всего курса — `math`, `json`, `csv` — просто это были модули, написанные разработчиками Python, а не нами самими. Теперь мы напишем и подключим свой собственный.

## Два способа импорта

Предположим, у нас есть файл `helpers.py` с одной функцией:

**Файл `helpers.py`:**
```python
def greet(name):
    return f"Привет, {name}!"
```

Подключить эту функцию в другом файле можно двумя способами.

**Способ 1: import модуль целиком**

```python
import helpers

print(helpers.greet("Егорь"))
```

Здесь обращение к функции происходит через имя модуля с точкой — `helpers.greet(...)`, точно так же, как мы обращались к `math.sqrt()` в уроке 4.

**Способ 2: from модуль import конкретное имя**

```python
from helpers import greet

print(greet("Егорь"))
```

Здесь функция `greet` подключается напрямую, без необходимости писать имя модуля перед каждым вызовом. У этого удобства есть обратная сторона — то, о чём пойдёт речь дальше.

## Проблема: конфликт имён

Представим, что в одной программе понадобилось использовать сразу два разных модуля, и оба называются похоже — например, оба содержат настройки, и оба файла названы `settings.py` в разных частях проекта, либо, что более реалистично, в обоих модулях объявлена переменная с одинаковым именем, скажем `settings`:

**Файл `app_settings.py`:**
```python
settings = {"theme": "тёмная", "language": "русский"}
```

**Файл `user_settings.py`:**
```python
settings = {"theme": "светлая", "notifications": True}
```

Если попытаться подключить обе переменные напрямую через `from ... import ...`, второй импорт молча перекроет первый:

```python
from app_settings import settings
from user_settings import settings

print(settings)
# {'theme': 'светлая', 'notifications': True} — от app_settings ничего не осталось
```

Оба импорта используют одно и то же имя `settings` в текущем файле, и, как мы уже знаем из урока 30, повторное присваивание одному и тому же имени просто заменяет предыдущее значение — вторая версия `settings` полностью вытеснила первую, без единой ошибки или предупреждения.

## Решение: import ... as ...

Оператор `as` позволяет присвоить импортируемому имени своё, отдельное название при подключении, устраняя конфликт:

```python
from app_settings import settings as app_settings
from user_settings import settings as user_settings

print(app_settings)   # {'theme': 'тёмная', 'language': 'русский'}
print(user_settings)  # {'theme': 'светлая', 'notifications': True}
```

Теперь оба набора настроек доступны одновременно, под разными, не пересекающимися именами. Тот же приём `as` работает и с `import модуль целиком`:

```python
import app_settings as app_cfg

print(app_cfg.settings)
```

## Разделение программы на модули

Разбиение программы на несколько файлов — это применение той же самой декомпозиции, о которой мы говорили в уроке 40, только теперь не на уровне отдельных функций внутри одного файла, а на уровне файлов внутри всего проекта. Логически связанный код — например, все функции для работы с файлами — удобно вынести в отдельный модуль, а не хранить вперемешку с остальной логикой программы.

## Константы и отдельный файл конфигурации

Значения, которые не должны меняться в ходе выполнения программы, — так называемые **константы**, — принято называть заглавными буквами с подчёркиванием между словами, и часто выносить в отдельный модуль, обычно называемый `config.py`:

**Файл `config.py`:**
```python
MAX_ATTEMPTS = 3
DEFAULT_CITY = "Москва"
APP_VERSION = "1.0.0"
```

**Файл `main.py`:**
```python
from config import MAX_ATTEMPTS

print(f"Максимум попыток: {MAX_ATTEMPTS}")
```

Обратите внимание: заглавные буквы в имени `MAX_ATTEMPTS` — это лишь соглашение, а не техническое ограничение Python. Ничто физически не мешает изменить значение такой переменной позже в коде, но сложившаяся договорённость сообщает всем, кто читает код: «это значение задумано как неизменное, трогать его не стоит».

## if __name__ == "__main__"

У каждого модуля есть встроенная переменная `__name__`, значение которой зависит от того, как модуль был запущен. Если файл запущен напрямую (например, командой `python helpers.py`), значение `__name__` внутри этого файла равно строке `"__main__"`. Если же этот же файл подключён через `import` из другого файла, `__name__` внутри него равен имени самого модуля (например, `"helpers"`), а не `"__main__"`.

Это позволяет писать код, который выполняется, только если файл запущен напрямую, а не был просто подключён откуда-то ещё:

**Файл `helpers.py`:**
```python
def greet(name):
    return f"Привет, {name}!"


if __name__ == "__main__":
    print(greet("Тест"))
```

Если запустить `helpers.py` напрямую, строка `print(greet("Тест"))` выполнится, потому что `__name__` в этот момент равен `"__main__"`. Но если этот же файл подключить через `import helpers` из другого файла, блок под `if __name__ == "__main__":` не выполнится вовсе — `__name__` в этом случае будет равен `"helpers"`, а не `"__main__"`, и условие окажется ложным.

Такой подход удобен для тестирования: можно держать в модуле и переиспользуемые функции, и небольшой пример их использования "для себя" — и этот пример не будет случайно выполняться каждый раз, когда модуль подключают откуда-то ещё, мешая работе основной программы.

## Пакеты и __init__.py — краткий обзор

Когда модулей становится много, их удобно объединять не только логически, но и физически — в папки. Папка, содержащая несколько связанных модулей, называется **пакетом**, если внутри неё присутствует специальный файл `__init__.py`:

```
project/
├── main.py
└── utils/
    ├── __init__.py
    ├── strings.py
    └── numbers.py
```

Здесь `utils` — пакет, потому что содержит `__init__.py`, а сам этот файл может быть пустым — одного его присутствия достаточно, чтобы Python рассматривал папку как пакет, из которого можно импортировать модули:

```python
from utils.strings import some_function
```

Мы не будем подробно разбирать все тонкости работы с пакетами, относительные импорты внутри них и содержимое `__init__.py` за пределами простого обозначения пакета — это выходит за рамки базового курса. Важно другое: увидев в чужом (или будущем собственном, более крупном) проекте папку с файлом `__init__.py` внутри, вы теперь понимаете, что перед вами — пакет, специально организованная группа модулей, а не просто случайная папка.

## Итоги урока

Модуль — это файл `.py`, код которого можно подключить в другом файле через `import модуль` (обращение через точку) или `from модуль import имя` (прямое обращение без префикса). Конфликт одинаковых имён при импорте из разных модулей решается оператором `as`, присваивающим импортированному имени собственное название. Разделение программы на несколько модулей — применение декомпозиции на уровне файлов проекта; константы для такого разделения принято выносить в отдельный модуль конфигурации и называть заглавными буквами. Проверка `if __name__ == "__main__":` позволяет выполнять код только при прямом запуске файла, а не при его подключении через импорт. Пакет — это папка с модулями, помеченная файлом `__init__.py`.
