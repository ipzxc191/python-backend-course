# Урок 50. Открытие и закрытие файлов. Режимы работы (r, w, a, r+). Контекстный менеджер with

В прошлом уроке мы разобрались, что такое файл и зачем он нужен. Пришло время научиться реально работать с файлами из Python — открывать их, выбирать, что именно мы собираемся с ними делать, и правильно завершать работу.

## Функция open()

Чтобы начать работать с файлом, его нужно открыть с помощью встроенной функции `open()`, указав путь к файлу и режим работы:

```python
file = open("notes.txt", "w")
```

Результатом `open()` становится специальный объект файла, через который и происходит вся дальнейшая работа — чтение или запись. Если файл `"notes.txt"` не существовал в рабочей папке программы, при таком вызове он будет создан.

## Режимы работы с файлом

Второй аргумент `open()` — режим — определяет, что именно вы собираетесь делать с файлом. Разберём четыре основных режима.

**`"r"` (read — чтение)** — режим по умолчанию, если вообще не указать режим явно. Открывает файл только для чтения. Если файл не существует, возникнет ошибка:

```python
file = open("notes.txt", "r")
```

**`"w"` (write — запись)** — открывает файл для записи. Если файла не существовало, он будет создан; если существовал — **всё его прежнее содержимое будет немедленно стёрто**, ещё до того, как вы запишете хоть один символ. Это важно запомнить: `"w"` не дописывает к существующему содержимому, а полностью его заменяет.

```python
file = open("notes.txt", "w")
```

**`"a"` (append — добавление)** — тоже открывает файл для записи, но, в отличие от `"w"`, не стирает существующее содержимое, а добавляет новые данные в конец файла, после всего, что там уже было:

```python
file = open("notes.txt", "a")
```

**`"r+"` (чтение и запись)** — открывает существующий файл сразу и для чтения, и для записи, не стирая его содержимое при открытии (в отличие от `"w"`). Требует, чтобы файл уже существовал, — в этом режиме, в отличие от `"w"` и `"a"`, новый файл автоматически не создаётся.

```python
file = open("notes.txt", "r+")
```

## Закрытие файла: close()

После того как работа с файлом завершена, его обязательно нужно закрыть методом `close()`:

```python
file = open("notes.txt", "w")
file.write("Привет, файл!")
file.close()
```

`write()` мы подробно разберём уже в следующем уроке — сейчас важнее понять, зачем вообще нужен `close()`.

## Почему забытый close() — это проблема

Здесь стоит разобраться в причине, а не просто запомнить правило "всегда закрывайте файл". Когда вы записываете данные в файл, они не всегда попадают на диск немедленно — по соображениям эффективности данные какое-то время могут накапливаться во временном буфере в оперативной памяти, и лишь при закрытии файла этот буфер гарантированно сохраняется на диск целиком. Если файл не закрыть явно, часть записанных данных рискует так и остаться в буфере, не долетев до диска, — особенно если программа завершится не совсем штатно.

Есть и более общая проблема: пока файл открыт, он занимает системный ресурс — своего рода "место в очереди" операционной системы. Если программа открывает много файлов подряд и ни один не закрывает, рано или поздно она упрётся в ограничение на количество одновременно открытых файлов, и попытка открыть ещё один файл завершится ошибкой.

Есть и третья, более тонкая проблема: что, если ошибка возникнет **в процессе** работы с файлом, где-то между `open()` и `close()`? Строка с `close()` в таком случае попросту не будет достигнута — выполнение прервётся раньше, а файл так и останется незакрытым.

## Решение: контекстный менеджер with

Python предлагает специальную конструкцию, которая решает все три проблемы сразу, — `with`:

```python
with open("notes.txt", "w") as file:
    file.write("Привет, файл!")
```

Здесь `with` открывает файл, присваивает его переменной `file` (через `as`) и гарантированно закрывает файл сам, как только выполнение покидает этот блок, — причём закрывает его **даже если внутри блока произошла ошибка**. Явно писать `file.close()` здесь не нужно — `with` берёт эту заботу на себя полностью, при любом сценарии завершения блока.

Сравните две версии одного и того же действия:

```python
# Без with — нужно не забыть close(), и это не защищает от ошибок в процессе работы
file = open("notes.txt", "w")
file.write("Привет, файл!")
file.close()

# С with — файл закроется сам, при любом исходе
with open("notes.txt", "w") as file:
    file.write("Привет, файл!")
```

Именно поэтому `with` считается стандартной, общепринятой практикой работы с файлами в Python — начиная с этого урока мы будем использовать исключительно эту форму, а `close()` вручную вызывать не будем вовсе.

## Проверка: файл действительно недоступен после закрытия блока with

Убедиться, что файл закрывается автоматически, можно, попытавшись обратиться к нему уже после выхода из блока `with`:

```python
with open("notes.txt", "w") as file:
    file.write("Привет!")

file.write("Ещё текст")
# ValueError: I/O operation on closed file
```

Вторая попытка записи, уже за пределами блока `with`, закономерно завершится ошибкой — файл к этому моменту действительно закрыт.

## Итоги урока

`open(путь, режим)` открывает файл и возвращает объект для работы с ним; `"r"` — чтение (по умолчанию), `"w"` — запись с полным стиранием существующего содержимого, `"a"` — добавление в конец без стирания, `"r+"` — чтение и запись без стирания, но требующее существующего файла. Файл обязательно нужно закрывать методом `close()` — иначе часть записанных данных может не попасть на диск, а сам файл будет продолжать занимать системный ресурс; при этом если ошибка произойдёт раньше вызова `close()`, файл вообще не закроется. Конструкция `with open(...) as file:` решает все эти проблемы разом, автоматически закрывая файл при любом сценарии завершения блока, и является стандартным способом работы с файлами в Python.
