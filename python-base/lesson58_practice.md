# Урок 58. Практика блока

Собираем весь блок в единый проект: несколько модулей, работающих вместе, глобальное состояние, изменяемое как через `global`, так и через изменение объекта на месте, вложенная функция с `nonlocal`, константы в отдельном файле и проверка `__main__`.

## Разбор с преподавателем: учёт расходов

Мы построим небольшое консольное приложение для учёта расходов. Строить будем в том порядке, в котором обычно работает программист: сначала решаем, **что хотим получить**, затем смотрим, **какие данные есть**, и только потом пишем код — причём каждую функцию пишем под конкретную потребность, а не «потому что так принято».

### Что мы хотим получить

Вот как должна выглядеть работа готовой программы. Вводимые пользователем значения идут после двоеточий:

```text
Команда (добавить/итого/категория/проверка/выход): добавить
Сумма: 1200
Категория: продукты
Команда (добавить/итого/категория/проверка/выход): добавить
Сумма: 75000
Категория: ремонт
Команда (добавить/итого/категория/проверка/выход): добавить
Сумма: 850
Категория: транспорт
Команда (добавить/итого/категория/проверка/выход): добавить
Сумма: 3400
Категория: продукты
Команда (добавить/итого/категория/проверка/выход): итого
Всего потрачено: 80450.0 руб.
Команда (добавить/итого/категория/проверка/выход): категория
Какая категория: продукты
  1200.0 руб.
  3400.0 руб.
Команда (добавить/итого/категория/проверка/выход): проверка

Команда (добавить/итого/категория/проверка/выход): выход
```

Мы внесли четыре расхода и получили от программы четыре вида ответов: сколько потрачено всего, какие траты были в категории «продукты», сколько расходов превысило лимит и сколько всего было записей. Эти четыре ответа и есть цель. Всё остальное в программе существует ради них.

### Какие данные у нас есть

Четыре расхода из примера выше — это исходные данные, с которыми будем работать весь разбор:

| № | Сумма | Категория |
|---|---|---|
| 1 | 1200 | продукты |
| 2 | 75000 | ремонт |
| 3 | 850 | транспорт |
| 4 | 3400 | продукты |

Один расход — это пара значений: сумма и категория. Естественно хранить его в словаре `{"amount": 1200.0, "category": "продукты"}`, а все расходы — в списке таких словарей.

### От вопросов к функциям

Теперь для каждого желаемого результата определим, что программе нужно уметь, и где это будет жить:

| Что мы хотим | Что для этого нужно | Где это будет |
|---|---|---|
| хранить все расходы | список словарей `expenses` | `storage.py` |
| знать, сколько всего записей | счётчик `expense_count` | `storage.py` |
| добавить новый расход | функция `add_expense(amount, category)` | `storage.py` |
| узнать общую сумму | функция `get_total()` | `storage.py` |
| выбрать расходы одной категории | функция `get_by_category(category)` | `storage.py` |
| сосчитать расходы сверх лимита | функция `check_expenses_limit(expenses)` | `validators.py` |
| хранить лимит `50000` и валюту `руб.` | константы `MAX_EXPENSE`, `CURRENCY` | `constants.py` |
| общаться с пользователем | меню в `main()` | `main.py` |

Так проект делится на четыре файла: **данные и операции над ними** (`storage.py`), **проверки** (`validators.py`), **неизменные значения** (`constants.py`) и **общение с пользователем** (`main.py`). Каждый файл отвечает за свою часть и не лезет в чужую: например, ни одна функция в `storage.py` не вызывает `input()` и `print()` — этим занимается только `main.py`.

Создайте в одной папке четыре пустых файла с этими названиями и будем наполнять их по очереди.

### Шаг 1. Файл `constants.py`

Начнём с самого простого. В нашей программе есть два значения, которые не меняются по ходу работы:

* лимит одного расхода: всё, что дороже **50000**, считаем подозрительно большим (в наших данных это расход № 2 на 75000);
* название валюты, которое мы добавляем к каждой сумме при выводе: **руб.**

```python
MAX_EXPENSE = 50000
CURRENCY = "руб."
```

Зачем выносить их в отдельный файл? Если завтра лимит понадобится поднять до 100000 или сменить валюту, мы поправим **одну строчку в одном файле**, а не будем искать числа по всей программе. Имена констант пишут ЗАГЛАВНЫМИ буквами — по ним сразу видно, что это значения, которые не должны меняться.

### Шаг 2. Файл `storage.py`

Этот файл — «склад» нашей программы: здесь живут сами данные и всё, что с ними делают.

#### Данные модуля

Сначала объявим две переменные на уровне модуля. Сразу после запуска программы у нас ещё нет ни одного расхода:

```python
expenses = []
expense_count = 0
```

Состояние в начале:

```text
expenses      = []
expense_count = 0
```

#### Функция `add_expense()` — добавить расход

Нужно, чтобы после вызова `add_expense(1200.0, "продукты")` в список попал новый расход, а счётчик вырос на единицу:

```python
def add_expense(amount, category):
    global expense_count
    expenses.append({"amount": amount, "category": category})
    expense_count += 1
```

Посмотрим, что происходит при четырёх вызовах — по очереди, как в нашем примере:

| Вызов | Что хранится в `expenses` | `expense_count` |
|---|---|---|
| `add_expense(1200.0, "продукты")` | `[{1200.0, продукты}]` | 1 |
| `add_expense(75000.0, "ремонт")` | `[{1200.0, продукты}, {75000.0, ремонт}]` | 2 |
| `add_expense(850.0, "транспорт")` | три расхода | 3 |
| `add_expense(3400.0, "продукты")` | четыре расхода | 4 |

После четырёх вызовов `expenses` выглядит так:

```python
[
    {"amount": 1200.0, "category": "продукты"},
    {"amount": 75000.0, "category": "ремонт"},
    {"amount": 850.0, "category": "транспорт"},
    {"amount": 3400.0, "category": "продукты"}
]
```

Обратите внимание на две разные строки внутри функции — они работают по-разному, и именно ради этого контраста мы всё и затевали.

**`expenses.append(...)`** — это **изменение списка на месте**. Мы не присваиваем имени `expenses` новое значение, а лишь дополняем уже существующий список. Поэтому `global` для него не нужен: Python находит `expenses` в модуле и добавляет в него элемент (урок 56).

**`expense_count += 1`** — это **присваивание**. Оно равносильно `expense_count = expense_count + 1`, а любое присваивание внутри функции Python по умолчанию считает созданием **локальной** переменной. Если не написать `global expense_count`, Python решит, что `expense_count` в этой функции — локальная, не найдёт в ней значения, которое нужно прочитать, и программа остановится с ошибкой:

```text
UnboundLocalError: cannot access local variable 'expense_count' where it is not associated with a value
```

Строка `global expense_count` говорит Python: «это не новая локальная переменная, а та самая, что объявлена на уровне модуля». После неё счётчик обновляется там, где нужно.

#### Функция `get_total()` — общая сумма

Для команды `итого` нужно сложить суммы всех расходов. Берём из каждого словаря значение по ключу `"amount"` и передаём в `sum()`:

```python
def get_total():
    return sum(expense["amount"] for expense in expenses)
```

На наших данных функция сложит `1200.0 + 75000.0 + 850.0 + 3400.0` и вернёт `80450.0`. Эта функция только читает `expenses` и ничего не присваивает, поэтому `global` ей тоже не нужен.

#### Функция `get_by_category()` — расходы одной категории

Для команды `категория` нужно из всего списка оставить только расходы с нужной категорией:

```python
def get_by_category(category):
    return [expense for expense in expenses if expense["category"] == category]
```

Вызов `get_by_category("продукты")` вернёт:

```python
[
    {"amount": 1200.0, "category": "продукты"},
    {"amount": 3400.0, "category": "продукты"}
]
```

А `get_by_category("спорт")` вернёт пустой список `[]` — расходов в такой категории нет.

Полностью файл `storage.py`:

```python
expenses = []
expense_count = 0


def add_expense(amount, category):
    global expense_count
    expenses.append({"amount": amount, "category": category})
    expense_count += 1


def get_total():
    return sum(expense["amount"] for expense in expenses)


def get_by_category(category):
    return [expense for expense in expenses if expense["category"] == category]
```

### Шаг 3. Файл `validators.py`

#### Для чего этот файл

В нашей задаче есть правило: расход больше `50000` — подозрительно большой. Нужно узнать, **сколько таких расходов** среди всех внесённых. На наших данных ответ — один (расход № 2 на 75000). Это и есть результат команды `проверка`: `Расходов сверх лимита: 1`.

Проверки — отдельная ответственность, поэтому выносим их в свой файл. Если потом появятся и другие проверки (например, пустая категория), для них уже есть место.

#### Откуда берётся лимит

Лимит мы не пишем в коде цифрой, а берём из `constants.py`:

```python
from constants import MAX_EXPENSE
```

#### Как работает подсчёт

Нам нужен счётчик, который растёт каждый раз, когда встретился расход выше лимита. Заведём его в теле функции, а проверку одного расхода вынесем во вложенную функцию:

```python
def check_expenses_limit(expenses):
    count_over_limit = 0

    def check_one(expense):
        nonlocal count_over_limit
        if expense["amount"] > MAX_EXPENSE:
            count_over_limit += 1

    for expense in expenses:
        check_one(expense)

    return count_over_limit
```

Проследим выполнение на наших четырёх расходах (лимит `50000`):

| Расход | `amount > 50000`? | `count_over_limit` после проверки |
|---|---|---|
| 1200.0 | нет | 0 |
| 75000.0 | **да** | 1 |
| 850.0 | нет | 1 |
| 3400.0 | нет | 1 |

После цикла функция возвращает `1`.

#### Зачем здесь `nonlocal`

Строка `count_over_limit += 1` — снова присваивание, а переменная `count_over_limit` создана **не во вложенной функции, а в окружающей**. Без `nonlocal` Python решил бы, что внутри `check_one()` появилась новая локальная переменная, не нашёл бы её значения и остановил бы программу такой же ошибкой `UnboundLocalError`. Слово `nonlocal` говорит: «эта переменная принадлежит ближайшей внешней функции — изменяй её, а не создавай новую». Это тот же приём, что `global`, но для вложенных функций (урок 56).

#### Что важно заметить

Функция принимает расходы **параметром** `expenses`, а не обращается к модулю `storage` напрямую. Поэтому `validators.py` вообще ничего не знает о том, откуда взялись расходы, — он просто проверяет любой переданный ему список. Откуда его взять, решит `main.py`.

### Шаг 4. Файл `main.py`

Теперь соберём всё вместе. `main.py` — единственный файл, который общается с пользователем: спрашивает команды, вызывает готовые функции и выводит результат. Сам он ничего не вычисляет.

#### Подключаем нужное

```python
from constants import CURRENCY
import storage
import validators
```

Обратите внимание, что импорты разные, и это не случайно:

* `from constants import CURRENCY` — валюта нужна нам просто как готовое значение, которое не меняется. Можно написать просто `CURRENCY`.
* `import storage` — мы хотим обращаться к `storage.expense_count` и `storage.expenses`, которые **меняются по ходу работы**. Если бы мы написали `from storage import expense_count`, то получили бы копию значения на момент импорта — число `0` — и оно навсегда осталось бы нулём, сколько бы расходов ни добавили. Через `storage.expense_count` мы каждый раз читаем актуальное значение из самого модуля (урок 57).

#### Шаг 4.1. Меню и команда `добавить`

Пока строим по одной команде. Основа — бесконечный цикл с запросом команды; первая ветка добавляет расход:

```python
def main():
    while True:
        command = input("Команда (добавить/итого/категория/проверка/выход): ")

        if command == "добавить":
            amount = float(input("Сумма: "))
            category = input("Категория: ")
            storage.add_expense(amount, category)
```

Пользователь вводит `1200` и `продукты`. `float("1200")` даёт `1200.0`, и `main()` отдаёт эти значения функции `storage.add_expense(1200.0, "продукты")`. Сам `main()` ничего не хранит: все данные живут в `storage`.

#### Шаг 4.2. Команда `итого`

```python
        elif command == "итого":
            print(f"Всего потрачено: {storage.get_total()} {CURRENCY}")
```

На наших данных `storage.get_total()` вернёт `80450.0`, а `CURRENCY` — `"руб."`, поэтому на экране появится `Всего потрачено: 80450.0 руб.`

#### Шаг 4.3. Команда `категория`

```python
        elif command == "категория":
            category = input("Какая категория: ")
            items = storage.get_by_category(category)
            for item in items:
                print(f"  {item['amount']} {CURRENCY}")
```

Пользователь вводит `продукты`, `get_by_category` возвращает список из двух словарей, и цикл выводит по строке на каждый расход: `1200.0 руб.` и `3400.0 руб.` Для категории без расходов список окажется пустым, цикл не выполнится ни разу, и ничего не будет выведено.

#### Шаг 4.4. Команда `проверка`

```python
        elif command == "проверка":
            count = validators.check_expenses_limit(storage.expenses)
            print(f"Расходов сверх лимита: {count}")
```

Именно здесь `main.py` связывает два модуля: берёт список расходов из `storage` и отдаёт его проверяющей функции из `validators`. Результат — `1`.

#### Шаг 4.5. Команда `выход` и неизвестные команды

```python
        elif command == "выход":
            print(f"Всего записей: {storage.expense_count}")
            break

        else:
            print("Неизвестная команда")
```

При выходе читаем счётчик прямо из модуля `storage` — после четырёх добавлений там `4`. Команда `break` завершает бесконечный цикл. Любой другой ввод попадает в `else`.

#### Шаг 4.6. Запуск только из этого файла

В самом конце файла:

```python
if __name__ == "__main__":
    main()
```

Когда мы запускаем файл `main.py` напрямую, Python записывает в служебную переменную `__name__` значение `"__main__"`, и меню запускается. Если же какой-то другой файл сделает `import main`, то внутри `main.py` в `__name__` окажется имя модуля, условие не выполнится, и программа не начнёт задавать вопросы сама собой в момент импорта.

#### Файл `main.py` целиком

```python
from constants import CURRENCY
import storage
import validators


def main():
    while True:
        command = input("Команда (добавить/итого/категория/проверка/выход): ")

        if command == "добавить":
            amount = float(input("Сумма: "))
            category = input("Категория: ")
            storage.add_expense(amount, category)

        elif command == "итого":
            print(f"Всего потрачено: {storage.get_total()} {CURRENCY}")

        elif command == "категория":
            category = input("Какая категория: ")
            items = storage.get_by_category(category)
            for item in items:
                print(f"  {item['amount']} {CURRENCY}")

        elif command == "проверка":
            count = validators.check_expenses_limit(storage.expenses)
            print(f"Расходов сверх лимита: {count}")

        elif command == "выход":
            print(f"Всего записей: {storage.expense_count}")
            break

        else:
            print("Неизвестная команда")


if __name__ == "__main__":
    main()
```

### Шаг 5. Запуск и проверка

Запустите `main.py` и проведите тот самый сеанс, что был показан в начале разбора: добавьте четыре расхода из таблицы и выполните команды `итого`, `категория` (с категорией `продукты`), `проверка` и `выход`. Результаты должны совпасть с эталоном: `80450.0 руб.`, две строки по продуктам, `1` расход сверх лимита и `4` записи.

Проследим, как менялось состояние программы по ходу этого сеанса:

| Что сделал пользователь | Кто сработал | Что изменилось или что вернулось |
|---|---|---|
| `добавить 1200, продукты` | `main` → `storage.add_expense` | `expenses` — 1 запись, `expense_count = 1` |
| `добавить 75000, ремонт` | `main` → `storage.add_expense` | 2 записи, `expense_count = 2` |
| `добавить 850, транспорт` | `main` → `storage.add_expense` | 3 записи, `expense_count = 3` |
| `добавить 3400, продукты` | `main` → `storage.add_expense` | 4 записи, `expense_count = 4` |
| `итого` | `main` → `storage.get_total` | вернулось `80450.0`, состояние не менялось |
| `категория продукты` | `main` → `storage.get_by_category` | вернулись 2 расхода, состояние не менялось |
| `проверка` | `main` → `validators.check_expenses_limit` | вернулось `1`, состояние не менялось |
| `выход` | `main` читает `storage.expense_count` | вывелось `4`, цикл завершён |

Видно, что **меняют** состояние только добавления, а все остальные команды его лишь читают. Это и есть главная идея разделения на модули: данные и операции над ними живут в `storage.py`, проверки — в `validators.py`, неизменные значения — в `constants.py`, а `main.py` только связывает всё воедино и общается с пользователем.

Если вы хотите убедиться, что поняли роль `global`, попробуйте убрать строку `global expense_count` из `add_expense()` и выполнить команду `добавить`: вы увидите ту самую ошибку `UnboundLocalError`. То же самое можно сделать с `nonlocal` в `validators.py`. Верните строки на место — программа снова заработает.

## Самостоятельная работа: учёт тренировок

Теперь ваша очередь. Вы соберёте похожий по структуре проект — трекер тренировок — но на другом материале и с несколькими отличиями от разбора. Эти отличия сделаны специально: если просто заменить слова в разобранном примере, программа не заработает так, как нужно.

### Что нужно получить

Вот как должна выглядеть работа готовой программы. Вводимые пользователем значения идут после двоеточий:

```text
Команда (добавить/среднее/тип/проверка/выход): добавить
```

### Данные, на которых мы проверяем программу

В примере выше внесено пять тренировок:

| № | Длительность (мин.) | Тип |
|---|---|---|
| 1 | 45 | бег |
| 2 | 200 | плавание |
| 3 | 30 | бег |
| 4 | 180 | йога |
| 5 | 210 | велосипед |

Лимит одной тренировки — **180 минут**. Превышением считается длительность **строго больше** лимита, поэтому тренировка № 4 (ровно 180) превышением **не** является. Превышение — это количество минут сверх лимита:

| № | Длительность | Превышение |
|---|---|---|
| 1 | 45 | 0 |
| 2 | 200 | 20 |
| 3 | 30 | 0 |
| 4 | 180 | 0 |
| 5 | 210 | 30 |
| | | **Сумма: 50** |

Именно так получается ответ `50` для команды `проверка`.

### Что должно получиться на этих данных

Ваши функции можно проверять по отдельности, не запуская меню. После добавления пяти тренировок из таблицы:

| Что проверяем | Ожидаемый результат |
|---|---|
| `storage.workouts` | список из пяти словарей |
| `storage.workout_count` | `5` |
| `get_average_duration()` | `133.0` |
| `get_by_type("бег")` | `[{'duration': 45, 'type': 'бег'}, {'duration': 30, 'type': 'бег'}]` |
| `get_by_type("танцы")` | `[]` |
| `calculate_total_excess(storage.workouts)` | `50` |

А ещё на пустых данных (до добавления любой тренировки): `get_average_duration()` возвращает `0`, а `calculate_total_excess([])` — тоже `0`.

### Чем это отличается от разобранного примера

В отличие от учёта расходов:

* вместо общей суммы (`итого`) здесь считается **средняя длительность** (команда `среднее`);
* вместо количества расходов сверх лимита здесь считается **суммарное превышение в минутах** (команда `проверка`);
* для среднего значения нужно позаботиться о случае, когда тренировок ещё нет (делить на ноль нельзя).

Остальная структура — модули, `global`, `nonlocal`, константы, `__main__` — вам знакома.

### Из чего состоит проект

| Файл | За что отвечает | Зачем он нужен |
|---|---|---|
| `constants.py` | неизменные значения | лимит и единица измерения лежат в одном месте и правятся в одном месте |
| `storage.py` | данные и операции над ними | список тренировок и счётчик, добавление, среднее, выбор по типу |
| `validators.py` | проверка лимита | расчёт суммарного превышения |
| `main.py` | общение с пользователем | единственный файл, где есть `input()` и `print()` |

### Что должно быть в каждом файле

**`constants.py`**

| Имя | Значение | Назначение |
|---|---|---|
| `MAX_DURATION_MINUTES` | `180` | лимит одной тренировки в минутах |
| `UNIT` | `"мин."` | единица измерения, которая добавляется к числам при выводе **и** в подсказке ввода длительности |

**`storage.py`**

Переменные модуля:

| Имя | Начальное значение | Что хранит |
|---|---|---|
| `workouts` | `[]` | список тренировок; каждая — словарь с ключами `"duration"` и `"type"` |
| `workout_count` | `0` | количество добавленных тренировок |

Счётчик `workout_count` нужен именно как отдельная переменная, а не как `len(workouts)`. Так в одном модуле оказываются обе ситуации из этого блока: изменение списка на месте и присваивание отдельной переменной.

Функции:

| Функция | Что делает | Что возвращает |
|---|---|---|
| `add_workout(duration, workout_type)` | добавляет в `workouts` словарь с длительностью и типом и увеличивает `workout_count` на 1 | ничего |
| `get_average_duration()` | считает среднюю длительность всех тренировок, округляя до двух знаков после запятой | среднее число; если тренировок нет — `0` |
| `get_by_type(workout_type)` | отбирает тренировки, тип которых полностью совпадает с переданным | список словарей |

Ни одна из функций не вызывает `input()` и `print()`.

**`validators.py`**

| Функция | Что делает | Что возвращает |
|---|---|---|
| `calculate_total_excess(workouts)` | суммирует, на сколько минут каждая тренировка превышает лимит | суммарное превышение в минутах; если превышений нет — `0` |

Требование к устройству функции: заведите счётчик суммарного превышения в теле `calculate_total_excess()`, а внутри неё — вложенную функцию, которая проверяет **одну** тренировку и, если она длиннее лимита, увеличивает счётчик через `nonlocal`. Внешняя функция вызывает вложенную в цикле по всем тренировкам и возвращает итог. Лимит берите из `constants.py`, а не записывайте числом.

**`main.py`**

Главная функция `main()` в бесконечном цикле спрашивает команду. Приглашение: `Команда (добавить/среднее/тип/проверка/выход): `. Команды:

| Команда | Что делает программа |
|---|---|
| `добавить` | запрашивает `Длительность (мин.): ` (целое число) и `Тип тренировки: `, вызывает `storage.add_workout(...)` |
| `среднее` | выводит `Средняя длительность: <число> мин.` |
| `тип` | запрашивает `Какой тип: `, выводит каждую найденную тренировку отдельной строкой с двумя пробелами в начале и единицей измерения, например `  45 мин.`; если подходящих нет — ничего не выводит |
| `проверка` | вызывает `validators.calculate_total_excess(storage.workouts)` и выводит `Суммарное превышение лимита: <число> мин.` |
| `выход` | выводит `Всего тренировок: <число>` (значение берётся из `storage.workout_count`) и завершает цикл |
| любая другая | выводит `Неизвестная команда` |

Дополнительные условия:

* единицу измерения в подсказке ввода и в выводе берите из константы `UNIT`, а не пишите текстом;
* вызов `main()` оберните в `if __name__ == "__main__":`;
* считайте, что пользователь всегда вводит корректные данные (число там, где нужно число); тип тренировки сравнивается точно, с учётом регистра букв.

### Рекомендуемый порядок работы

1. Создайте в одной папке четыре файла.
2. Напишите `constants.py` — два значения.
3. Напишите `storage.py`. Проверьте функции отдельно: создайте временный файл, подключите `storage`, добавьте тренировки из таблицы данных и сверьте результаты `get_average_duration()` и `get_by_type()` с таблицей ожидаемых значений. Не забудьте проверить среднее для пустого списка.
4. Напишите `validators.py` и проверьте `calculate_total_excess()` на тех же данных: должно получиться `50`; на пустом списке — `0`.
5. Напишите `main.py`: сначала цикл с командой `добавить`, потом по одной остальные команды.
6. Проведите сеанс из начала задания и сверьте весь вывод.
