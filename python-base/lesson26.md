# Урок 26. Итератор и итерируемые объекты. Функции iter() и next()

Мы уже несколько уроков подряд пишем `for element in something:`, и это просто работает — какой бы `something` ни оказался: список, строка, `range()`. Настало время заглянуть внутрь и понять, что на самом деле происходит в этот момент. Тема концептуально непростая, но она того стоит — она объясняет саму суть того, чем мы занимались всё это время, не задумываясь.

## Итерируемый объект — то, по чему можно пройтись

**Итерируемый объект** (iterable) — это любой объект, по которому можно пройтись циклом `for`: список, строка, `range()`. Но сам по себе итерируемый объект не «помнит», на каком элементе он сейчас находится, — он лишь умеет предоставить то, что действительно это помнит: **итератор**.

**Итератор** — это отдельный объект, который умеет отдавать элементы по одному, каждый раз следующий, и при этом помнит, на каком месте он остановился в прошлый раз. Именно итератор, а не сам список или строка, отслеживает текущую позицию перебора.

## Получаем итератор: функция iter()

Чтобы получить итератор из итерируемого объекта, используется функция `iter()`:

```python
numbers = [10, 20, 30]
iterator = iter(numbers)

print(iterator)
# <list_iterator object at 0x...>
```

`iterator` — это уже не тот же самый список, а отдельный, специальный объект, назначение которого — по одному отдавать значения из этого списка и запоминать, докуда он уже дошёл.

## Получаем значения по одному: функция next()

Чтобы получить следующее значение из итератора, используется функция `next()`:

```python
numbers = [10, 20, 30]
iterator = iter(numbers)

print(next(iterator))   # 10
print(next(iterator))   # 20
print(next(iterator))   # 30
```

Каждый вызов `next()` возвращает следующее значение и одновременно продвигает внутреннюю «отметку» итератора на шаг вперёд. Обратите внимание: сам список `numbers` при этом никак не меняется — вся информация о том, «докуда дошли», хранится внутри `iterator`, а не внутри списка.

## Что происходит, когда элементы заканчиваются

Если вызвать `next()` ещё раз, когда все элементы уже отданы, произойдёт ошибка:

```python
numbers = [10, 20, 30]
iterator = iter(numbers)

next(iterator)   # 10
next(iterator)   # 20
next(iterator)   # 30
next(iterator)
# StopIteration
```

`StopIteration` — специальный сигнал о том, что элементы в итераторе закончились. Это не «поломка» и не ошибка в привычном смысле, а именно сигнал, специально предназначенный для того, чтобы что-то другое могло его поймать и отреагировать соответствующим образом.

## Вот что на самом деле делает for

Теперь можно раскрыть главный секрет этого урока: цикл `for` — это не какая-то отдельная, особая магия. Он делает ровно то же самое, что мы только что проделали вручную: один раз вызывает `iter()`, чтобы получить итератор, а затем в цикле вызывает `next()`, пока не поймает `StopIteration` — и именно в этот момент, поймав сигнал об окончании, он тихо и корректно завершает цикл, ни разу не показав вам саму эту ошибку.

Если бы `for` не существовал как готовая конструкция, вы могли бы написать его аналог вручную, примерно так:

```python
numbers = [10, 20, 30]
iterator = iter(numbers)

while True:
    try:
        value = next(iterator)
    except StopIteration:
        break
    print(value)
```

Здесь используется конструкция `try`/`except`, с которой мы подробно познакомимся значительно позже в курсе, — она перехватывает ошибку, вместо того чтобы дать ей остановить программу. Пока не нужно вникать в её синтаксис — достаточно понять главное: `for numbers in ...: print(value)` — это по сути свёрнутая, готовая версия ровно этого кода. `for` берёт на себя вызов `iter()`, повторяющиеся вызовы `next()` и перехват `StopIteration` — всё то, что в примере выше пришлось бы делать руками.

## range() — тоже итерируемый объект, а не готовый список

Здесь стоит развеять одно частое заблуждение: `range(5)` — это не список чисел, заранее лежащий где-то в памяти. Это отдельный, особый вид итерируемого объекта, который умеет порождать числа по требованию, одно за другим, не храня заранее весь набор целиком:

```python
r = range(5)
print(type(r))   # <class 'range'>

numbers_list = list(r)
print(numbers_list)   # [0, 1, 2, 3, 4]
```

Только когда мы явно превращаем `range(5)` в список функцией `list()`, Python действительно создаёт список со всеми пятью числами сразу. Пока `range(5)` остаётся просто `range`-объектом, числа порождаются по одному, ровно в тот момент, когда цикл `for` (через `iter()` и `next()`) их запрашивает — а не все сразу заранее. У этого устройства есть практическая польза, к которой мы ещё вернёмся в одном из следующих модулей: не обязательно хранить в памяти сразу миллион чисел, если можно порождать их по одному, ровно тогда, когда они нужны.

## Итоги урока

Итерируемый объект (список, строка, `range()`) — это то, по чему можно пройтись циклом `for`, но само по себе оно не отслеживает текущую позицию перебора. Итератор — отдельный объект, получаемый функцией `iter()`, который умеет отдавать элементы по одному через `next()` и помнит, докуда уже дошёл; когда элементы заканчиваются, `next()` порождает сигнал `StopIteration`. Цикл `for` — это, по сути, готовая, свёрнутая версия ручного вызова `iter()` и повторяющегося `next()` с перехватом `StopIteration`, только эта работа скрыта от вас и происходит автоматически. В обычном коде `iter()`/`next()` вручную почти не используются — этот урок был не про новый рабочий инструмент, а про понимание того, что на самом деле стоит за уже привычным `for`.

В следующем уроке мы объединим сразу две темы, которые естественно дополняют друг друга, — вложенные циклы и вложенные списки.
