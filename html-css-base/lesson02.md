# Урок 2. Блочные и строчные элементы. `div` и вложенность

## Коротко о прошлом уроке

В Уроке 1 мы разобрали основы: тег — это команда браузеру в угловых скобках, у большинства тегов есть открывающая и закрывающая часть (`<p>...</p>`), у некоторых — только самозакрывающаяся форма (`<img>`). Мы познакомились с первыми тегами — `h1`–`h6`, `p`, `a`, `img` — и с тем, как подключается CSS (внешний файл, `<style>` в `<head>`, inline через атрибут `style`), а также с базовой структурой CSS-правила: селектор → свойство → значение.

Сегодня разберём, почему эти теги на странице ведут себя по-разному — одни выстраиваются друг под другом, другие остаются в строке текста, — и познакомимся с `<div>`, универсальным контейнером, без которого не обходится ни одна веб-страница.

---

## Блочные и строчные элементы

**Блочный элемент** — элемент, который браузер по умолчанию выводит как отдельный «блок»: занимает всю доступную ширину родителя и всегда начинается с новой строки. Из уже знакомых тегов блочными являются `h1`–`h6` и `p`.

**Строчный (inline) элемент** — элемент, который «встраивается» в текущую строку текста, занимает ровно столько места, сколько нужно его содержимому, и не создаёт разрыва строки сам по себе. Из знакомых тегов строчным является `a`. Тег `img` занимает особое положение — технически это «замещаемый» строчный элемент: он остаётся в строке текста, но при этом (в отличие от обычных строчных элементов вроде `a`) у него работают свойства `width`/`height`.

Понимать эту разницу важно по одной простой причине: она напрямую определяет, как будет выглядеть страница. Заголовки и абзацы всегда идут вертикально, один под другим — это блочное поведение. Ссылки и мелкие изображения остаются частью текста в строке — это строчное поведение.

### Ментальная модель: полки и коробки

Представь веб-страницу как книжную полку. **Блочные элементы** — это коробки: каждая занимает отдельное место по вертикали, ставится одна под другой, и если коробка широкая — она займёт всю ширину полки. **Строчные элементы** — это книги или фигурки, которые ставятся рядом друг с другом на одной полке: можно поставить несколько книг подряд, пока не закончится место, — тогда следующие автоматически «переедут» на новую полку.

### Демонстрация: `h1` и `p` — блочные элементы

```html
<h1>Заголовок: блочный элемент</h1>
<p>Это абзац — ещё один блочный элемент. Обрати внимание, что он начинается с новой строки.</p>
```

```css
h1 {
  color: white;
  background-color: #2b6cb0;
}

p {
  color: #222;
  background-color: #f0f0f0;
}
```

Оба фона растянутся на всю ширину страницы, и `p` окажется строго под `h1`, даже если текста в нём совсем немного, — именно так ведёт себя «коробка» на полке.

### Демонстрация: `span` и `a` — строчные элементы

Познакомимся ещё с одним тегом — `<span>`. Это строчный аналог `div`: сам по себе он ничего не значит, просто позволяет выделить кусок текста внутри строки, чтобы стилизовать именно его.

```html
<p>Текст перед <span>встроенным span</span> и <a href="#">ссылкой</a> в одной строке.</p>
```

```css
span {
  background-color: yellow;
  color: black;
}

a {
  background-color: yellow;
  color: red;
}
```

Фон здесь охватывает только сам текст внутри `span` и `a` — «жёлтый кусочек» посреди строки, а не всю ширину страницы, как было с `h1`/`p`.

### Демонстрация: `img` — строчный, но «замещаемый»

```html
<p>Текст слева <img src="https://picsum.photos/100" alt="Картинка" /> и текст справа.</p>
```

Картинка встанет прямо в строку между двумя кусками текста — как и положено строчному элементу. Но если задать ей `width`/`height`, размер реально изменится — обычный строчный элемент (например, `span`) так себя не ведёт, у него `width`/`height` попросту не работают, пока он остаётся строчным.

## Тег `div` — универсальный контейнер

`<div>` — блочный контейнер общего назначения. Он не несёт никакого смысла сам по себе (в отличие от `h1` или `p`, которые сообщают браузеру и поисковым системам, что перед ними заголовок или абзац) — зато он идеально подходит для того, чтобы сгруппировать несколько элементов вместе и применить стили ко всей группе разом.

Представь карточку профиля: фотография, имя, короткое описание. Обернув всё это в один `div`, можно задать этому `div` фон, отступы, размеры — и вся карточка получит единое оформление, как цельный блок, а не набор разрозненных элементов.

```html
<div>
  <h1>Имя</h1>
  <p>Описание</p>
</div>
```

### Простая стилизация `div`

`div` — блочный элемент, поэтому к нему применимы `width` и `height`. Если `width` не задан явно, `div` растянется на всю ширину родителя.

```html
<div>Это мой div</div>
```

```css
div {
  width: 400px;
  height: 200px;
  background-color: #f7c6c6;
  color: #222;
}
```

Результат — прямоугольник 400×200px с заданным фоном. Если ширина окна браузера меньше 400px, блок будет выходить за границы экрана — это нормально, про адаптивность мы поговорим в отдельном уроке позже.

### Вложенность: `div` как родитель

**Вложенность** — когда один элемент находится внутри другого. Вся структура HTML-документа устроена как дерево: у элементов есть родители и дети. `div` очень часто выступает именно родителем — контейнером для группы дочерних элементов.

```html
<div>
  <h1>Иван Иванов</h1>
  <p>Короткое описание: студент, изучаю веб.</p>
  <img src="https://picsum.photos/120" alt="avatar" />
</div>
```

```css
div {
  width: 360px;
  background-color: #e6f7ff;
  padding: 10px;
}

h1 {
  color: #1a3d6b;
}

p {
  color: #333;
}

img {
  display: block;
  margin-top: 10px;
}
```

Две новые детали здесь заслуживают отдельного объяснения:

- **`padding`** — внутренний отступ элемента, расстояние между границей блока и его содержимым внутри. Подробно свойства блочной модели (`padding`, `margin`, `border`) разберём в следующем уроке — здесь достаточно знать, что без него содержимое `div` прижималось бы вплотную к его краям.
- **`display: block`** у `img` — картинка по умолчанию строчная (см. предыдущий раздел), и если рядом с ней есть текст, она встанет прямо в строку. `display: block` меняет её поведение на блочное — картинка переходит на новую строку и ведёт себя как отдельный блок, а не часть текстовой строки.

### Наследование стилей — что переходит от родителя к потомку, а что нет

Важный нюанс, который легко упустить: не все свойства, заданные родителю, автоматически применяются к вложенным элементам.

| Свойство | Наследуется от родителя? |
|---|---|
| `color` | Да |
| `font-size`, `font-family` | Да |
| `text-align` | Да |
| `background-color` | Нет |
| `width`, `height` | Нет |
| `padding`, `margin`, `border` | Нет |

Например, если задать `div` цвет текста (`color`) — все вложенные `h1` и `p` унаследуют этот цвет текста, если не переопределят его собственным правилом. Но если задать `div` `background-color` — это не «прольётся» на дочерние элементы, фон останется только у самого `div` как у контейнера. Это разделение полезно держать в голове с самого начала — оно объясняет неожиданное на первый взгляд поведение стилей, с которым вы ещё не раз столкнётесь.
