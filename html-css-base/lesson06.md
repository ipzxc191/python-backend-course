# Урок 6. Работа со списками (`ul`, `ol`, `dl`). Стилизация списков. Псевдоклассы и псевдоэлементы

## Зачем нужны списки

Списки — один из фундаментальных блоков HTML: они упорядоченно представляют несколько однородных элементов — пункты меню, шаги инструкции, перечень характеристик, набор ссылок. Используя список вместо набора обычных абзацев, вы сообщаете браузеру и вспомогательным технологиям (экранным читалкам, поисковым роботам): «это именно перечисление». Семантика делает код понятнее не только человеку, но и машине — это напрямую влияет на доступность и SEO.

### Базовые теги списков

`<ul>` (unordered list) — ненумерованный список, когда порядок элементов не важен: меню, перечень характеристик, набор ссылок.

```html
<ul>
  <li>Молоко</li>
  <li>Хлеб</li>
  <li>Яйца</li>
</ul>
```

`<ol>` (ordered list) — нумерованный список, когда порядок важен: шаги инструкции, ранжированный перечень.

```html
<ol>
  <li>Включить питание</li>
  <li>Подключить кабель</li>
  <li>Запустить приложение</li>
</ol>
```

`<li>` — элемент списка, всегда находится внутри `<ul>` или `<ol>`.

`<dl>`/`<dt>`/`<dd>` — описательный список («термин — определение»), удобен для спецификаций, FAQ, пар «вопрос — ответ»:

```html
<dl>
  <dt>HTML</dt>
  <dd>язык разметки для веб-страниц</dd>
  <dt>CSS</dt>
  <dd>язык стилей для оформления</dd>
</dl>
```

Разные теги важны потому, что подразумевают разную роль для вспомогательных технологий: экранный читалка, встретив `<ol>`, может объявить «список из N пунктов» и озвучить номер текущего — это упрощает навигацию. Если сделать то же самое через голые `<div>`, стилизованные «под список», эта встроенная информация теряется.

### Где применяются списки

Навигационные меню (`<ul><li><a>…</a></li></ul>` — почти всегда именно так), перечни товаров/преимуществ/шагов, хлебные крошки (`<ol>`, потому что там важен порядок), чек-листы, спецификации (`<dl>`). Главное правило: используйте списки там, где по смыслу действительно есть перечисление — не ради удобства стилизации, а потому что семантика важнее.

### Поведение браузера по умолчанию

Браузер даёт `<ul>`/`<ol>` внутренний отступ слева (обычно около 40px), чтобы маркеры не налезали на текст; `<li>` получает маркер (точка/кружок для `ul`, номер для `ol`); `<dt>` обычно жирный, `<dd>` — с отступом. Прежде чем стилизовать список под конкретный дизайн, обычно делают базовый сброс:

```css
ul,
ol {
  margin: 0;
  padding: 0;
}

ul {
  list-style: none; /* убираем стандартные маркеры */
}
```

## Стилизация списков

### Убираем маркеры: `list-style: none`

```css
ul {
  list-style: none;
}
```

Полезно, когда вы хотите контролировать вид списка полностью через CSS — например, поставить свои иконки или собрать горизонтальное меню. Важная деталь для доступности: даже без визуальных маркеров список остаётся полностью семантичным — экранный читалка по-прежнему видит его как список. Но если маркеры несут смысловую нагрузку (например, в чек-листе), замените их собственными через `::before`, а не просто убирайте.

### Позиция маркера: `list-style-position`

`outside` (по умолчанию) — маркер рисуется слева вне блока содержимого, перенос текста идёт с отступом от маркера. `inside` — маркер внутри блока содержимого, перенесённая строка выравнивается уже под самим маркером, без дополнительного отступа.

```css
ul {
  list-style-position: inside;
}
```

### Кастомные маркеры

Самый простой способ — `list-style-image`, но у него слабый контроль над размером и позицией в разных браузерах:

```css
ul {
  list-style-image: url("/icons/bullet.svg");
}
```

Более гибкий способ — псевдоэлемент `::before` у `<li>`, дающий полный контроль над размером, цветом и положением маркера:

```css
li::before {
  content: "•";
  color: crimson;
  display: inline-block;
  width: 1em;
  margin-right: 0.5em;
}
```

Более подробно псевдоэлементы разберём отдельным разделом ниже.

### Горизонтальное меню через `inline-block`

```css
ul.menu {
  padding: 0;
  margin: 0;
  list-style: none;
  text-align: center;
}

ul.menu li {
  display: inline-block;
  margin: 0 10px;
}
```

Напомним разницу (Урок 3): `display: inline` не позволяет управлять шириной/высотой элемента, `inline-block` сохраняет расположение в строке, но при этом ведёт себя как блок — именно поэтому для меню используют `inline-block`, а не голый `inline`.

**Побочный эффект `inline-block`:** между соседними `<li>` в HTML-коде появляется небольшой промежуток — браузер интерпретирует перенос строки/пробел между тегами как обычный текстовый пробел. Самое простое решение — убрать пробелы между тегами в самой разметке (`<li>...</li><li>...</li>`, без переноса строки между ними). Более редкая альтернатива — временно занулить `font-size` у родителя и восстановить его у `li`:

```css
ul.menu {
  font-size: 0;
}
ul.menu li {
  font-size: 16px;
}
```

Для меню на этом уровне курса первого способа (убрать пробелы в разметке) вполне достаточно.

### Кликабельная зона ссылки

```css
ul.menu li a {
  display: inline-block;
  padding: 10px 15px;
  color: #333;
  text-decoration: none;
}
```

Делая саму ссылку `inline-block` с внутренними отступами, а не только текст, мы расширяем зону, по которой удобно попасть курсором или пальцем — особенно важно на мобильных устройствах.

## Навигация: тег `<nav>`

`<nav>` — семантический контейнер именно для основной навигации: набора ссылок, которые переводят пользователя по разделам сайта. Он сигнализирует браузеру и вспомогательным технологиям «здесь меню» — экранные читалки могут сразу переходить к навигации, поисковики понимают, где расположены важные ссылки, а разработчику, читающему код, сразу видно назначение блока.

`<nav>` используется для блока ссылок, предназначенных именно для навигации (главное меню, меню в футере, навигация по разделам сайта) — но не для одиночной ссылки вроде «читать далее» внутри статьи.

**Глобальная навигация** — основное меню сайта, обычно в шапке, ведёт по разделам всего сайта. **Локальная навигация** — навигация внутри конкретного раздела или статьи (например, оглавление статьи). Оба вида можно оформлять через `<nav>`, если по смыслу это действительно набор ссылок для перемещения:

```html
<nav class="site-nav">... глобальное меню ...</nav>
<article>
  <nav class="article-nav">... ссылки по разделам статьи ...</nav>
</article>
```

Горизонтальная навигация обычно уместна в шапке, при небольшом числе пунктов (3–8) — выстраивается через `inline-block` (или `float` в старых проектах, как мы разбирали в Уроке 5). Вертикальная — уместна в сайдбаре, при большом числе пунктов или вложенных категориях, выстраивается через обычный `display: block` для ссылок в колонке.

## Псевдоклассы: состояния и структура

**Псевдокласс** — селектор, выбирающий уже существующие элементы документа по их состоянию или положению в структуре, без добавления чего-либо в HTML.

```html
<ul class="menu">
  <li><a href="#">Главная</a></li>
  <li><a href="#">Каталог</a></li>
  <li><a href="#">Новости</a></li>
  <li><a href="#">Контакты</a></li>
  <li><a href="#">О компании</a></li>
</ul>
```

### Интерактивные псевдоклассы

`:hover` — стиль при наведении курсора мыши. `:focus` — элемент получил фокус (обычно через `Tab` или клик) — критически важен для доступности: пользователь, работающий с клавиатуры, должен видеть, на каком элементе он сейчас находится. `:focus-visible` — более современный вариант: срабатывает преимущественно при клавиатурной навигации, а не при обычном клике мышью (мы уже разбирали этот псевдокласс применительно к `input`/`button`). `:active` — состояние в момент нажатия. `:visited` — стиль для уже посещённых ссылок (современные браузеры сильно ограничивают, какие свойства через него можно менять, по соображениям приватности).

```css
.menu a {
  display: inline-block;
  padding: 8px 12px;
  text-decoration: none;
  color: #333;
}

.menu a:hover,
.menu a:focus,
.menu a:focus-visible {
  background: #eee;
  color: #000;
}

.menu a:active {
  transform: translateY(1px);
}
```

**Важное правило безопасности доступности:** если убираете стандартный `outline` у `:focus`, обязательно замените его на другой заметный визуальный эффект (например, `box-shadow`) — иначе пользователь, работающий с клавиатуры, теряет возможность понять, где сейчас находится фокус.

### Правильный порядок объявления состояний ссылки

Исторически принятый порядок для ссылок — `:link`, `:visited`, `:hover`, `:focus`, `:active` (мнемоника «LVHA»). Порядок важен: при одинаковой специфичности побеждает правило, объявленное позже, — если, например, написать `:hover` раньше `:active`, а пользователь одновременно наводит и нажимает, может неожиданно применяться не то правило, которое ожидалось.

```css
.menu a:link {
  color: #2b6cb0;
}

.menu a:visited {
  color: #6b6b6b;
}

.menu a:hover,
.menu a:focus,
.menu a:focus-visible {
  background: #eee;
}

.menu a:active {
  transform: translateY(1px);
}
```

### Структурные псевдоклассы

`:first-child` — элемент, являющийся первым ребёнком своего родителя.

```css
.menu li:first-child {
  font-weight: bold;
}
```

---

`:last-child` — последний ребёнок.

```css
.menu li:last-child {
  color: crimson;
}
```

---

`:nth-child(n)` — элемент по формуле-позиции; принимает `odd`/`even`, `2n`, `3n+1` и конкретные числа; нумерация начинается с 1.

```css
.menu li:nth-child(even) {
  background: #f3f3f3;
}
```

---

`:nth-of-type()` — аналогично, но считает только элементы указанного типа тега среди детей — полезно, когда среди детей смешаны разные теги.

Добавляем один посторонний элемент.

```html
<ul class="menu">
  <li><a href="#">Главная</a></li>
  <li><a href="#">Каталог</a></li>

  <p>Рекламный блок</p>

  <li><a href="#">Новости</a></li>
  <li><a href="#">Контакты</a></li>
  <li><a href="#">О компании</a></li>
</ul>
```

```css
.menu li:nth-child(even) {
  background: #ffeeba;
}

.menu li:nth-of-type(even) {
  border: 2px solid green;
}
```

---

`:not(селектор)` — исключает элементы, подходящие под указанный селектор.

```css
.menu li:not(:last-child)::after {
  content: " |";
}
```

---

`:nth-child(2n)` эквивалентно `:nth-child(even)` (2, 4, 6…), `:nth-child(2n+1)` эквивалентно `:nth-child(odd)` (1, 3, 5…). Если внутри родителя вперемешку разные теги, а «зебру» нужно строго по `li` — надёжнее `li:nth-of-type(even)`, чем `li:nth-child(even)`, потому что `nth-of-type` считает позицию только среди элементов одного типа тега, игнорируя остальные.

## Псевдоэлементы: `::before` и `::after`

**Псевдоэлемент** создаёт виртуальный дочерний элемент перед или после содержимого реального элемента. Он участвует в рендере страницы (можно задать размер, фон, позиционирование), но не существует как узел в DOM — то есть не появляется в HTML-разметке и не виден, например, при просмотре исходного кода страницы.

Обязательное правило: у псевдоэлемента должно быть задано свойство `content` (даже пустой строкой), иначе он не будет создан:

```css
li::after {
  content: "";
}
```

### Практические применения

**Разделитель между пунктами меню** — без добавления лишних `<span>` в разметку:

```css
.menu li:not(:last-child)::after {
  content: "|";
  margin-left: 10px;
  color: #ccc;
}
```

**Декоративная иконка** вместо стандартного маркера:

```css
li::before {
  content: "";
  display: inline-block;
  width: 16px;
  height: 16px;
  background-image: url("icon.png");
  background-size: contain;
  margin-right: 8px;
  vertical-align: middle;
}
```

**Стрелка (caret) у пункта с подменю:**

```css
li.has-sub > a::after {
  content: " ▾";
  margin-left: 6px;
  transition: transform 0.2s;
}

li.has-sub:hover > a::after {
  transform: rotate(180deg);
}
```

**Метка на основе `data`-атрибута** — гибкий способ выводить произвольный текст без жёсткого дублирования в CSS:

```html
<li class="product" data-badge="новинка">Товар B</li>
```

```css
.product::after {
  content: attr(data-badge);
  color: #c00;
  margin-left: 6px;
  display: none;
}

.product[data-badge]::after {
  display: inline;
}
```

### Ограничения и правило доступности

Не храните в `::before`/`::after` смысловой, важный для понимания контент — сгенерированный таким образом текст не всегда читается экранными читалками надёжно, недоступен для копирования и не индексируется поисковиками так же, как обычный текст. Используйте псевдоэлементы для декорации (разделители, иконки, второстепенные пометки) — а если метка действительно важна по смыслу (например, статус товара), продублируйте её в настоящей разметке (`<span class="badge">Новинка</span>`), а псевдоэлемент оставьте только для чисто визуальных украшений.

Также псевдоэлементы не работают с «заменяемыми» элементами вроде `<img>` или `<input>` — применяйте их к обычным контейнерам (`li`, `a`, `div`).

> Отдельного упоминания заслуживает современный псевдоэлемент `::marker`, который позволяет стилизовать сам стандартный маркер списка напрямую (`li::marker { color: red; }`), без замены его на `::before` — удобная альтернатива для простых случаев, когда достаточно поменять только цвет или размер маркера.

## Выпадающее меню на чистом CSS

Разберём законченный пример подменю — вложенный `<ul>` внутри `<li>`, показываемый при наведении и при фокусе клавиатуры.

```html
<nav class="site-nav">
  <ul>
    <li><a href="#">Главная</a></li>
    <li class="has-sub">
      <a href="#" aria-haspopup="true">Каталог</a>
      <ul class="dropdown">
        <li><a href="#">Категория A</a></li>
        <li><a href="#">Категория B</a></li>
      </ul>
    </li>
    <li><a href="#">Контакты</a></li>
  </ul>
</nav>
```

**Самый простой вариант** — скрывать подменю через `display: none` и показывать на `:hover`:

```css
.site-nav .dropdown {
  display: none;
  position: absolute;
}

.site-nav li:hover > .dropdown {
  display: block;
}
```

Проблема: `display` нельзя плавно анимировать (переход происходит мгновенно), а `display: none` полностью исключает элемент из потока и из порядка табуляции — сфокусироваться на скрытый элемент с клавиатуры невозможно.

**Более удачный вариант** — управлять `opacity`/`visibility`/`transform` вместо `display`, и добавить `:focus-within` для поддержки клавиатуры:

```css
.site-nav li {
  position: relative;
  display: inline-block;
}

.site-nav .dropdown {
  position: absolute;
  left: 0;
  top: 100%;
  opacity: 0;
  visibility: hidden;
  transform: translateY(8px);
  transition: opacity 0.15s ease, transform 0.15s ease;
  background: white;
  box-shadow: 0 6px 12px rgba(0, 0, 0, 0.08);
  min-width: 160px;
  padding: 8px 0;
}

.site-nav li:hover > .dropdown,
.site-nav li:focus-within > .dropdown {
  opacity: 1;
  visibility: visible;
  transform: translateY(0);
}

.site-nav .dropdown li {
  display: block;
}

.site-nav .dropdown a {
  display: block;
  padding: 8px 16px;
}
```

`visibility: hidden` вместе с `opacity: 0` скрывает подменю визуально, при этом сохраняя плавность через `transition`. `:focus-within` — псевдокласс, который становится истинным, если фокус находится **где-то внутри** элемента (например, пользователь табом попал на ссылку «Каталог» внутри `li`) — благодаря этому подменю раскрывается и при клавиатурной навигации, без единой строчки JavaScript.

`aria-haspopup="true"` у ссылки-родителя сообщает вспомогательным технологиям, что у пункта есть подменю. Полноценное управление `aria-expanded` (раскрыто/свёрнуто), обработка `Esc` для закрытия и стрелок для перемещения между пунктами подменю — это уже задачи, требующие JavaScript, и выходят за рамки чисто CSS-решения. На touch-устройствах `:hover` ведёт себя не всегда предсказуемо, поэтому `:focus-within` — не просто «бонус для клавиатуры», а практическая опора и для сенсорных экранов, где первый тап часто эквивалентен получению фокуса.

**Вывод:** CSS-only выпадающее меню — хороший, рабочий вариант для учебных и небольших проектов, но полноценная, доступная реализация с полным управлением состоянием и клавиатурными шорткатами в реальных продакшн-проектах обычно требует JavaScript.
