# Урок 7. Работа с изображениями и фоном (`img`, `background`). Стилизация background с помощью изображений и/или градиента

## `<img>` и его атрибуты

### `src` — источник изображения

Самый главный атрибут — путь к файлу изображения, локальный или внешний URL.

```html
<img src="images/cat.jpg" alt="Рыжий кот лежит на диване" />
```

Без `src` картинка просто не появится.

### `alt` — альтернативный текст

Один из самых важных атрибутов, выполняющий сразу несколько функций: **доступность** (скринридеры озвучивают содержимое `alt` для людей с нарушением зрения), **SEO** (поисковые системы используют `alt`, чтобы понять, что изображено), **fallback** (если картинка не загрузится — из-за ошибки или медленного интернета — вместо неё покажется текст из `alt`).

Пустой `alt=""` пишется, если картинка чисто декоративная и не несёт смысловой нагрузки (иконка, фоновый узор) — так вы явно говорите скринридеру: «игнорируй это изображение». Осмысленный `alt` нужен, если картинка важна для понимания контента (фото товара, схема, иллюстрация в статье).

```html
<!-- Картинка имеет смысл, alt обязателен -->
<img src="product.jpg" alt="Ноутбук Lenovo ThinkPad X1 Carbon, вид сверху" />

<!-- Декоративная картинка, alt пустой -->
<img src="decor-line.png" alt="" />
```

### `width` и `height` — размеры изображения

Современная практика — указывать размеры изображения прямо в HTML, а не только через CSS. Причина: браузер заранее резервирует место под картинку ещё до её загрузки, что предотвращает **layout shift** — неприятные «скачки» вёрстки, когда уже загруженный текст страницы вдруг сдвигается вниз в момент, когда наконец подгрузилась картинка.

```html
<img src="banner.jpg" alt="Рекламный баннер" width="1200" height="400" />
```

Даже пока картинка не загрузилась, браузер оставит под неё прямоугольник 1200×400 пикселей. Адаптивное поведение (`max-width: 100%; height: auto;`) при этом задаётся в CSS отдельно — базовые же размеры лучше указывать именно в HTML.

### `loading="lazy"` — ленивая загрузка

Говорит браузеру не загружать изображение сразу, а подгрузить его только тогда, когда пользователь доскроллит до нужного места — это экономит трафик и ускоряет первоначальную загрузку страницы.

```html
<img src="gallery/photo1.jpg" alt="Фото природы" width="800" height="600" loading="lazy" />
```

Используйте `loading="lazy"` для изображений, не видных сразу на первом экране. Для логотипа в шапке или первой картинки на странице лучше грузить сразу (без этого атрибута), иначе пользователь какое-то время будет видеть пустое место в самой важной, первой видимой части страницы.

### `decoding="async"`

Подсказка браузеру, как обрабатывать декодирование картинки: `sync` декодирует картинку сразу, что может замедлить прорисовку страницы; `async` декодирует в фоне, не блокируя рендеринг. Для большинства случаев стоит использовать именно `decoding="async"`.

### Итоговый пример правильной разметки

```html
<img
  src="images/photo.jpg"
  alt="Фотография офиса нашей компании"
  width="800"
  height="500"
  loading="lazy"
  decoding="async"
/>
```

Здесь указано всё важное: источник, текст для доступности, размеры (против скачков вёрстки), ленивая загрузка и подсказка браузеру по декодированию.

## `object-fit` и `object-position`

Когда мы задаём `<img>` фиксированные `width`/`height`, а исходная картинка имеет другие пропорции, возникают проблемы: изображение искажается (лица становятся «сплющенными»), или обрезается непредсказуемо, или оставляет пустые поля там, где хотелось бы, чтобы картинка заполняла всё пространство. `object-fit` решает именно эту задачу — определяет, как изображение вписывается в заданную ему рамку.

`object-fit` работает только для **замещаемых элементов** (replaced elements) — тех, чьё содержимое приходит извне: `<img>`, `<video>`, `<iframe>`.

### Значения `object-fit`

**`fill`** (по умолчанию) — изображение заполняет контейнер целиком, пропорции не сохраняются, картинка может исказиться. Подходит редко, в основном для декоративных случаев.

**`contain`** — изображение вписывается полностью, пропорции сохраняются; если форма картинки не совпадает с контейнером, остаются пустые поля (виден фон контейнера). Хорошо подходит для логотипов и иконок, где важно не обрезать ничего.

**`cover`** — изображение полностью покрывает контейнер, пропорции сохраняются, но часть картинки может быть обрезана. Хорошо подходит для галерей и карточек, где важнее заполнить блок, чем показать изображение целиком.

**`none`** — изображение не подстраивается под контейнер вообще, используются реальные размеры картинки — внутри контейнера видна только часть.

**`scale-down`** — браузер сравнивает результат `none` и `contain` и выбирает тот вариант, при котором картинка окажется меньше; полезно, когда важно не увеличивать картинку сверх её оригинального размера.

```css
.fit-cover {
  width: 100%;
  height: 100%;
  object-fit: cover;
}
```

На практике чаще всего используются именно `contain` (иконки, логотипы) и `cover` (карточки, галереи) — думайте об `object-fit` как об аналоге `background-size`, только для `<img>`.

### `object-position`

Если изображение обрезается (при `cover` или `none`), нужно управлять тем, какая именно часть остаётся видимой. По умолчанию это центр (`50% 50%`). Значение можно задавать ключевыми словами (`top center`, `left bottom`), процентами (`0% 0%` — левый верхний угол) или пикселями.

```html
<div class="card">
  <img src="portrait.jpg" alt="Портрет" class="fit-focus" />
</div>
```

```css
.card {
  width: 300px;
  height: 200px;
  overflow: hidden;
}

.fit-focus {
  width: 100%;
  height: 100%;
  object-fit: cover;
  object-position: top center;
}
```

Изображение «приближается» через `cover`, но `object-position: top center` гарантирует, что в видимой области останется именно верхняя часть кадра (например, лицо), а не случайно обрезанный низ.

## `background-image` — фон как декоративный элемент

### Когда `background-image`, а когда `<img>`

`<img>` — контентное изображение, важное для смысла страницы (фото товара, иллюстрация к статье): оно должно сопровождаться `alt`, быть доступным для скринридеров, индексироваться поисковиками. `background-image` — декоративное изображение: фон баннера, текстура, градиентная подложка — не несёт смысловой нагрузки, служит только стилизации.

**Практическое правило:** для карточек товаров и контентных изображений используйте `<img>`; для больших «геро-блоков» (hero sections), баннеров и декоративных элементов — `background-image`.

```css
.hero {
  width: 100%;
  height: 300px;
  background-image: url("hero.jpg");
  border: 2px solid #333;
}
```

### `background-repeat`

По умолчанию фоновое изображение повторяется, если оно меньше контейнера: `repeat` (по умолчанию, повтор в обе стороны), `repeat-x` (только по горизонтали), `repeat-y` (только по вертикали), `no-repeat` (без повтора, картинка показывается один раз).

```css
.pattern {
  background-image: url("pattern.png");
  background-repeat: repeat-x;
}
```

### `background-position`

Управляет тем, где именно в контейнере располагается изображение — ключевые слова (`top`, `bottom`, `left`, `right`, `center`), их комбинации (`top right`), проценты (`20% 50%`) или пиксели (`10px 30px`).

```css
.position-demo {
  background-image: url("logo.png");
  background-repeat: no-repeat;
  background-position: right bottom;
}
```

### `background-size`

Контролирует, как картинка вписывается в контейнер: `auto` (по умолчанию, оригинальный размер), `cover` (полностью покрывает контейнер, часть может обрезаться — та же логика, что и у `object-fit: cover`), `contain` (полностью помещается внутрь, могут остаться пустые поля), либо явные значения ширины/высоты (`100px 50px`, `50% auto`).

```css
.hero {
  background-image: url("hero.jpg");
  background-size: cover;
  background-position: center;
}
```

### `background-attachment`

Определяет поведение фона при прокрутке страницы: `scroll` (по умолчанию, фон прокручивается вместе с содержимым), `fixed` (фон остаётся закреплённым на экране — классический эффект параллакса), `local` (фон прокручивается вместе с содержимым конкретного элемента, если у него своя внутренняя прокрутка — используется редко).

```css
.parallax {
  height: 100vh;
  background-image: url("mountains.jpg");
  background-size: cover;
  background-attachment: fixed;
}
```

При прокрутке страницы текст «уезжает» вверх, а горы на фоне остаются на месте. Важная оговорка: `background-attachment: fixed` плохо работает на многих мобильных устройствах — часть браузеров отключает эту поддержку для оптимизации производительности прокрутки.

### `background-blend-mode`

Позволяет «смешивать» фоновое изображение с цветом или градиентом, подобно режимам наложения слоёв в графических редакторах: `multiply`, `overlay`, `screen`, `darken`, `lighten`.

```css
.hero {
  background-image: url("hero.jpg");
  background-color: rgba(0, 0, 0, 0.5);
  background-blend-mode: multiply;
  background-size: cover;
}
```

Картинка затемняется полупрозрачным слоем — удобный способ сделать текст поверх фото читаемым, не редактируя саму картинку в графическом редакторе заранее.

### Множественные фоновые изображения

CSS позволяет указать сразу несколько фоновых слоёв через запятую — они накладываются друг на друга, как слои в графическом редакторе. **Важно про порядок:** первый указанный слой рисуется сверху, следующий — под ним, и так далее.

```css
.hero {
  background-image: linear-gradient(to bottom, rgba(0, 0, 0, 0.5), rgba(0, 0, 0, 0.8)),
    url("hero.jpg");
  background-size: cover;
  background-position: center;
}
```

Здесь градиент указан первым — значит, он рисуется поверх картинки и плавно затемняет её снизу вверх, делая текст, размещённый в блоке, более читаемым.

### Сокращённая запись (shorthand)

Самое частое сочетание свойств удобно записывать одной строкой:

```css
background: url("hero.jpg") no-repeat center/cover;
```

Здесь одной строкой заданы `background-image`, `background-repeat`, `background-position` (до слэша) и `background-size` (после слэша).

## Практические выводы и подводные камни

- `cover` заполняет блок, возможно обрезая края; `contain` показывает всю картинку целиком, возможно с пустыми полями — выбор зависит от того, что важнее в конкретном случае.
- Контролируйте фокус кадра через `background-position`/`object-position`, если важная часть изображения (лицо, логотип) рискует быть обрезанной при `cover`.
- Для seamless-паттернов нужны специально подготовленные, идеально стыкующиеся по краям изображения — иначе повтор будет выдавать видимые швы.
- Фоновые изображения не читаются скринридерами — если картинка несёт смысл, ей место в DOM как `<img>` с `alt`, а не в `background-image`.
- `background-attachment: fixed` часто плохо работает на мобильных устройствах — тестируйте эффект параллакса на реальных телефонах, а не только на десктопе.
